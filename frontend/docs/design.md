# FIT 디자인 규격

화면을 만들 때 숫자를 새로 고르지 않기 위한 문서입니다. 코드에서는
`src/constants/theme.ts` 의 이름으로만 씁니다.

> 전에 이 문서는 토스 디자인 시스템의 값을 적어 두었는데 코드는 그 사이
> 다른 값으로 옮겨 가 있었습니다. 문서를 읽고 만든 화면이 틀린 색으로
> 나왔습니다. 아래는 **코드에 실제로 들어 있는 값**입니다.

---

## 원칙 셋

1. **흑백입니다.** 강조색이 따로 없고, 가장 진한 것이 곧 강조입니다.
2. **직각입니다.** 카드·단추·입력칸·시트에 둥근 모서리가 없습니다.
3. **도형을 줄입니다.** 상자보다 선, 선보다 여백. 화면에 둘 곳이 하나여야
   눈이 헤매지 않습니다.

셋 다 같은 것을 노립니다 — 색과 모서리와 그림자로 끌던 눈길을 **글자의
크기와 굵기, 그리고 빈자리**가 대신하게 하는 것.

---

## 1. 색

무채색 아홉 단계뿐입니다.

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `text` | `#0E0E0E` | 본문, 그리고 주 동작(검정 단추) |
| `textSecondary` | `#5A5A5A` | 보조 설명 |
| `textMuted` | `#8A8A8A` | 곁다리 |
| `textDisabled` | `#B0B0B0` | 못 누르는 것 |
| `borderStrong` | `#D2D2D2` | 진한 선(시트·다이얼로그 테두리) |
| `border` | `#E4E4E4` | 선 |
| `fillPressed` | `#EFEFEF` | 눌렸을 때 |
| `fill` | `#F7F7F7` | 눌러 앉은 자리 |
| `background` / `surface` | `#FFFFFF` | 종이 |

`accent` 는 `text` 와 같은 값이고, `danger`·`success`·`hot` 도 마찬가지
입니다. **색으로 못 가리는 것은 모양으로 가립니다** — 아래 2절.

### 지도만 예외

날짜를 가르는 색 여섯은 그대로 둡니다. 지도의 핀과 동선, 그리고 목록의
날짜 표시가 같은 색을 씁니다.

```
#2563EB  #F97316  #059669  #9333EA  #E11D48  #0891B2
```

바탕 회색을 어느 쪽으로도 기울이지 않은 것이 이 때문입니다. 바탕이
따뜻하거나 차면 이 여섯이 제 색으로 보이지 않습니다.

---

## 2. 색 없이 세기를 나누는 법

단추 넷의 차이는 **채움과 테두리**입니다.

| | 생김새 | 쓰는 곳 |
|---|---|---|
| `primary` | 검정으로 꽉 채움 | 화면의 주 동작. 한 화면에 하나 |
| `secondary` | 흰 바탕 + 가는 선 | 곁들이는 선택지 |
| `danger` | 흰 바탕 + **1.5px 선** | 되돌릴 수 없는 것 |
| `ghost` | 아무것도 없음 | 있어도 그만인 것 |

빨강을 뺀 자리를 굵은 테두리가 대신합니다. 그리고 그 앞에는 늘 확인 판이
한 번 더 섭니다 — 모양만으로 부족한 몫을 절차가 채웁니다.

같은 원리가 다른 데도 적용됩니다.

- **띠 탭** — 고른 칸 아래 2px 선. 밝기 차이가 아니라 있고 없음이라
  흑백에서 갈립니다.
- **뱃지** — 채움이 아니라 가는 테두리.
- **입력칸** — 상자가 아니라 밑줄. 쓰는 동안 그 줄이 검게 굵어집니다.
- **오류** — 상자가 아니라 왼쪽 세로선 한 줄.

---

## 3. 글자

색을 걷어 냈으므로 위계를 글자가 혼자 집니다. 그래서 단계 사이를 벌렸고,
큰 것일수록 더 좁게 붙였습니다.

| 이름 | 크기 / 줄 높이 | 자간 | 쓰는 곳 |
|---|---|---|---|
| `display` | 34 / 40 | −1.4 | 아주 큰 제목 |
| `title` | 26 / 33 | −1.0 | 화면 제목 (한 화면에 하나) |
| `heading` | 21 / 28 | −0.7 | |
| `subheading` | 18 / 26 | −0.5 | 카드 제목 |
| `body` | 16 / 25 | −0.3 | 본문, 입력칸, 단추 |
| `bodySmall` | 14 / 21 | −0.2 | 보조 본문 |
| `caption` | 12 / 18 | −0.1 | 메타 정보 |
| `label` | 11 / 16 | **+1.4** | 구역 이름표(대문자) |

`label` 만 자간이 넓습니다. 읽으라고 있는 것이 아니라 "여기서부터 다른
이야기" 라는 표시라, 화면에 글자가 늘어도 눈이 걸리지 않습니다.

굵기는 `regular 400` / `medium 500` / `semibold 600` / `bold 700` /
`heavy 800`. 흑백에서 "가장 강한 것" 을 만들 방법은 굵기뿐이라 800 을
두었습니다 — 워드마크가 씁니다.

---

## 4. 모서리·그림자

```
Radius = { none: 0, full: 999 }
```

`full` 은 **지도 핀과 도장에만** 씁니다. 핀은 어느 지도에서나 동그라미라
그것까지 각지게 하면 지도 위의 점이 UI 조각처럼 보이고, 네모난 도장은
도장으로 안 읽힙니다.

그림자(`Lift`)는 값이 전부 0 입니다. 이름은 남겨 두었습니다 — 언젠가 한
곳에서만 다시 띄우고 싶을 때 거기만 고치면 됩니다. 지도 위에 얹히는
판(`dragSheet`)만은 예외로 그림자를 답니다. 지도의 길과 색 위에서는 가는
선이 묻힙니다.

---

## 5. 치수

간격은 4의 배수로만: `xs 4 · sm 8 · md 12 · lg 16 · xl 20 · xxl 24 ·
xxxl 32 · huge 40`.

누르는 크기는 어떤 것도 44 아래로 내려가지 않습니다(애플 44pt, 구글 48dp,
WCAG 2.2 AAA 44px). 줄 안의 작은 단추는 보이기만 36 으로 두고
`hitSlop` 으로 44 를 채웁니다.

---

## 6. 로고

글자로 씁니다. 어느 크기로 키워도 뭉개지지 않고, 화면을 열 때 그림 파일을
기다리지 않습니다.

- **워드마크** — `FIT`, 굵기 800, 자간 −1.2. 붙어서 한 덩어리로 읽혀야
  합니다.
- **락업** — 워드마크 아래 `FALL INTO TRIP` 을 `label` 자간으로. 둘 다
  왼쪽에 세웁니다. 로고만 가운데고 아래 글이 왼쪽이면 축이 둘이 됩니다.

앱 아이콘은 그림이어야 하므로 `assets/images` 의 png 를 씁니다. 검은 바탕에
흰 `FIT` 이고, 글꼴 없이 사각형만으로 그렸습니다
(`F`·`I`·`T` 는 셋 다 가로세로 막대로만 이루어져 있습니다).

---

## 7. 말

- **서론을 쓰지 않습니다.** 위 막대가 이미 이름을 적고 있으면 본문에서
  또 소개하지 않습니다.
- **한 줄에 하나만.** 표식·제목·설명을 상자에 묶어 늘어놓으면 읽을 것이
  세 배가 되고, 그러면 아무것도 안 읽힙니다.
- **얻는 것으로 말합니다.** "로그인이 필요합니다" 는 우리 사정입니다.
  읽는 사람이 알고 싶은 것은 계정을 만들면 무엇이 되느냐입니다.
