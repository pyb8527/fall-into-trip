## 2. 소식함의 재료 — **셋에 시각이 없습니다**

`verdict.md` §11 이 `Place.updatedBy`·`updatedAt` 을 확인했습니다. 여기서는
`ideas.md` 가 재료로 적은 **나머지**를 확인한 결과를 남깁니다.

| 재료 | 시각 | 소식으로 만들 수 있나 |
|---|---|---|
| `Place.updatedAt` + `updatedBy` | 있음 | 됩니다 |
| `TripCandidate.createdAt` · `CandidateVote.createdAt` | 있음 | 됩니다 |
| `PostLike.createdAt` · `PostComment.createdAt` | 있음 | 됩니다 |
| `PostView.onDate` | **날짜만**(`LocalDate`) | 합계만. 시각순으로 못 섞습니다 |
| `TripItem` | `createdAt` 만 | **안 됩니다** — `done`·`ownerId` 가 바뀐 시각이 없습니다 |
| `TripMember` | **없음** | **안 됩니다** |
| `Day` | `version` 만 | **안 됩니다** |

그래서 `ideas.md` 의 보기 중 `민수님이 '어댑터'를 챙긴다고 했어요` 는
**지금 재료로 못 만듭니다.** 칸을 더하면 되지만, 소식이 실제로 읽히는지
본 뒤에 정합니다.

`AuditLog` 로는 대신할 수 없습니다. 색인 기준이 **누가 했는가**(`userId`)
라서 **누구에게 보일 것인가**로 뽑는 질의가 안 나옵니다. 부르는 자리가
41 곳이라 여기에 화면 사정을 섞으면 둘 다 못 고칩니다.

### 4.1 통화를 고를 수가 없습니다

`<Field label="비용" placeholder="￥1,200" />`. 사람이 통화 기호까지 손으로

`print.web.ts:158`. 정산에도 하루 합계에도 안 들어갑니다.

### 4.3 반대쪽은 서버에 이미 다 있습니다

없습니다. 프런트 `Spend` 타입에는 칸이 아예 없습니다.

### 걸리는 것

**사람이 자유롭게 적은 칸을 숫자로 읽지 않습니다.** 이미 적힌 `cost` 에는
`무료`·`1인 2천엔`·`￥1,200~1,800` 이 들어 있습니다. 마이그레이션이 값을
옮기면 틀린 돈이 정산에 들어갑니다. 기존 칸을 건드리지 않고 숫자 칸을
옆에 둡니다.

**사람이 수락해야 바뀝니다.** 계획한 비용이 저절로 지출이 되면 안 간 곳의
돈이 정산에 섞입니다. 미리 채워 주고 사람이 누릅니다.
