# 앱을 열지 않아도 며칠 남았는지 보인다 — 위젯 한 장

> `verdict.md` 14번에서 **조건부 찬성**으로 받은 것의 실행 계획입니다.
> 아직 코드는 한 줄도 바뀌지 않았습니다.
>
> **2차입니다.** `plan-app-offline.md` 와 한 번에 묶어 EAS 로 굽습니다.
>
> **조건이 하나 안 풀렸습니다.** §9 의 첫 물음(안드로이드 경로)에 답이 없으면
> 이 계획은 시작하지 않습니다. iOS 만 내지 않습니다.

## 1. 하려는 것

세는 일은 이미 끝났습니다. **밖으로 안 나갑니다.**

`frontend/src/lib/countdown.ts` 가 답을 냅니다 — `countdownOf(startIso, endIso)`
가 `going` · `tomorrow` · `left(days)` · `null` 넷 중 하나를 돌려주고(`:41-57`),
`countdownLabel`(`:77`)이 사람이 읽는 한 마디로 바꿉니다. 다녀온 여행에는
아무것도 안 냅니다 — "D+40" 은 알아서 뭐 하나 싶은 값이라서(`:33-34`).

그 답을 두 화면이 씁니다. 목록은 뱃지로(`app/(app)/trips.tsx:320-342`), 홈은
한 줄로(`app/(app)/home.tsx:65+`).

**그런데 둘 다 앱을 열어야 보입니다.** 사람들은 여행 전에 날짜를 셉니다.
앱이 없어도 하는 행동이고, 그 셈이 이미 정확히 되어 있는데 **잠금화면까지
가지 않습니다.**

TripIt 이 잠금화면 위젯으로 하는 일이 이것입니다.

## 2. 이미 있는 것

| 필요한 일 | 지금 어디에 있나 |
|---|---|
| 며칠 남았는지 세기 | `lib/countdown.ts:41` `countdownOf` |
| 사람이 읽는 말 | `lib/countdown.ts:77` `countdownLabel` |
| 가까운지 판단 | `countdownIsNear` (`trips.tsx:339` 가 씁니다) |
| 가장 가까운 여행 하나 고르기 | `app/(app)/home.tsx:65+` — 시작일이 이른 것부터 |
| 여행 목록 | `GET /api/trips` (`home.tsx:51-54`) |
| EAS 설정 자리 | `frontend/app.config.js` — 지금 안드로이드 지도 키만 얹습니다 |
| Expo 버전 조건 | `expo: ~57.0.20`. `expo-apple-targets` 가 요구하는 SDK 53 이상을 넘습니다 |

`home.tsx` 의 "가장 가까운 여행 하나" 고르는 규칙(주석 `:57-64`)이 위젯에
필요한 것과 똑같습니다 — "하나만 답니다. 둘 이상을 세로로 늘어놓으면 그것은
목록이고, 목록은 「내 여행」 이 이미 하는 일입니다."

## 3. 버리는 것

### 3.1 Live Activity — 버립니다

잠금화면 위젯만 합니다. Live Activity(잠금화면·Dynamic Island 에서 실시간
갱신)는 안 합니다.

여행 중에 내용을 바꾸려면 **밖에서 밀어 넣어야** 하고, 그건 푸시입니다.
`PushService`(`support/push/PushService.java:178` `tell`)가 이미 있지만, 알림
피로를 안 늘린다는 판단이 서 있습니다 — `docs/ideas.md:44-45` ("푸시를
늘리지 않습니다. 들어왔을 때만 보이므로 알림 피로가 0입니다").

D-day 는 하루에 한 번 바뀌는 값입니다. Live Activity 가 필요한 종류의
값이 아닙니다.

### 3.2 서버에서 위젯 값을 내려 주기 — 버립니다

위젯용 엔드포인트를 새로 만들지 않습니다. **앱이 깨어날 때 계산해서 기기에
써 둡니다.** `countdownOf` 는 날짜 두 개만 있으면 되는 순수 함수이고, 여행
목록은 이미 받아 옵니다.

위젯이 직접 우리 서버를 부르게 하면 (ㄱ) 위젯에 토큰을 줘야 하고
(ㄴ) 잠금화면이 갱신될 때마다 요청이 들어오고 (ㄷ) `GoogleQuotaFilter` 가
세는 "누구" 가 흐려집니다.

### 3.3 일정 내용을 위젯에 싣기 — 버립니다

"내일 09:20 간사이행" 같은 것을 위젯에 안 씁니다. **여행 이름과 남은 날
뿐입니다.**

잠금화면은 남이 봅니다. 카페 테이블에 폰을 놓아 두면 뒤에 선 사람이
읽습니다. 여행 이름은 사람이 스스로 지은 것이라 그 사람이 감수한 것이지만,
숙소 이름과 항공편은 아닙니다.

`Day.stayName`·`flight` 를 위젯에 내보내지 않습니다.

### 3.4 웹 — 버립니다

안 됩니다. 브라우저에 잠금화면이 없습니다. 이것은 온디바이스 모델에 이어
**웹과 앱이 갈리는 두 번째 자리**입니다. 그래서 §3.2 를 지킵니다 — 갈리는
것을 "위젯이 있는가" 하나로 좁히고, 그 아래 셈(`countdown.ts`)은 한 벌로
둡니다.

### 3.5 여러 개 보여 주기 — 버립니다

가장 가까운 여행 하나입니다. `home.tsx` 의 판단을 그대로 잇습니다.

## 9. 아직 모르는 것

- **안드로이드 위젯을 Expo CNG 로 넣는 길.** 조사에서 찾은 글은 전부 iOS
  얘기였습니다(`expo-apple-targets`, Expo Widgets). 안드로이드는 Jetpack
  Glance 라는 것까지만 압니다. **이 답이 없으면 이 계획을 시작하지 않습니다.**
  iOS 만 내면 이 저장소가 지켜 온 "갈라도 양쪽이 다 선다" 가 무너집니다.
- **`expo-apple-targets` 와 Expo Widgets 중 어느 것.** 후자는 2026 에 나온
  것이고 위젯을 React 컴포넌트로 정의합니다. 새것이라 얼마나 익었는지
  모릅니다. 전자는 SwiftUI 를 직접 씁니다.
- **Expo Go 로 못 보게 되는지.** `docs/done/recommend.md` §8.1 이 온디바이스
  모델 때 같은 문제를 적어 두었습니다 — config plugin 을 쓰는 순간 dev
  client 를 따로 구워야 합니다. 이미 `react-native-executorch` 가 들어가
  있으니 **이미 그 상태일 가능성이 큽니다.** 그렇다면 이 항목은 비용이
  아닙니다. 확인해야 합니다.
- **앱이 깨어날 때를 어떻게 잡는지.** `home.tsx` 를 열 때만 쓰면 홈을 안
  거치는 사람의 위젯이 안 갱신됩니다. `AppState` 를 봐야 하는데,
  `house-rules` 의 "WebSocket·SSE 는 과잉, `AppState` 처리가 먼저입니다"
  줄이 이것과 이어지는지 봐야 합니다.
- **앱이 실제로 쓰이는 비중.** `plan-app-offline.md` §9 와 같은 물음입니다.
  README 는 실제 서비스가 웹 빌드라고 적습니다. 웹에서 안 되는 기능이라
  (3.4) 이 계획의 값어치가 여기에 전부 달렸습니다.
