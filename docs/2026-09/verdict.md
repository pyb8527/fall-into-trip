### 0.1 `docs/done/recommend.md` 가 실제와 갈려 있습니다

이 문서를 쓰기 전에 밝혀 둡니다. `docs/done/recommend.md` 는 머리에 "아직 코드는
한 줄도 바뀌지 않았습니다" 라고 적혀 있지만, **그 문서의 0·1·2·3단계가 거의
다 들어가 있습니다.**

| `recommend.md` 의 단계 | 지금 상태 |
|---|---|
| 0단계 — Places API (New) | 됨. `PlaceSearchService` 가 `places.googleapis.com` 을 부릅니다 |
| 1단계 — 맥락 추천 | 됨. `trip/application/RecommendService.java`, `components/recommend-sheet.tsx`, `backend/src/test/http/recommend.test.mjs` |
| 2단계 — 서버 뒤 LLM | `IntentParser` 자리가 서 있음 (`RecommendService:89` 가 `Intent` 를 받습니다) |
| 3단계 — 온디바이스 | 됨. `react-native-executorch` + `lib/intent.ts` (Qwen 2.5 1.5B, 4비트) |
| §10 "웹용 WASM 모델 — 하지 않기로 한 것" | **했습니다.** `@mlc-ai/web-llm` + `lib/intent.web.ts` |

마지막 줄이 중요합니다. `recommend.md` 가 "하지 않기로 한 것" 에 적어 둔 것이
실제로는 들어갔습니다. 그러면 그 표는 다음 사람에게 거짓을 말합니다. 이번
계획과 별개로 고쳐야 합니다 — 아래 "순서" 의 0차에 두었습니다.

### 0.2 `GoogleQuotaFilter` 가 못 보는 종류의 값이 있습니다

이번 조사의 가장 쓸모 있는 발견이고, 후보 셋의 판정 근거입니다.

Places API (New) 는 **필드마스크에 무엇을 적었는지로** 요금 등급이 넷으로
갈립니다. `GoogleQuotaFilter.callsOf` 는 **호출 횟수**만 셉니다
(`:52-70`). 그래서 호출을 한 번도 더 안 하면서 청구액을 올리는 길이 있고,
문턱은 그것을 통과시킵니다.

지금 우리 위치:

| 자리 | 달라고 하는 것 | 등급 |
|---|---|---|
| `PlaceSearchService.FIELDS` | `id`·`displayName`·`formattedAddress`·`location`·`types`·`rating`·`userRatingCount` | **Enterprise** |
| `PlaceInfoService.FIELDS:77-86` | 위 + `regularOpeningHours`·`nationalPhoneNumber`·`websiteUri`·`businessStatus` | **Enterprise** |

`rating`·`userRatingCount` 때문에 이미 Pro 가 아니라 Enterprise 입니다.
그 위에 등급이 하나 더 있습니다 — **Enterprise + Atmosphere.** 최근 1년에
열린 필드가 대부분 거기 있습니다.

**그래서 이 문서는 후보마다 "요금 등급을 올리는가" 를 따로 셉니다.**
`callsOf` 의 숫자가 안 바뀌어도 값이 오르면, 그것은 값이 드는 것입니다.

## 4. 결과마다 거리·소요시간 (routingSummaries) — **반대**

### 이미 있는 것

`RecommendService.java:341,346` 이 이미 `distanceM` 을 돌려줍니다 — "여행의
한가운데(또는 지금 자리)에서 얼마나 떨어졌는지".

### 걸리는 것

**요금 등급**입니다. `routingSummaries` 는 **Enterprise + Atmosphere** —
넷 중 가장 비싼 등급입니다. 지금 우리는 Enterprise 이므로 한 칸 올라갑니다.

그리고 이 증가를 우리 문턱이 못 봅니다. `GoogleQuotaFilter.callsOf` 는 추천에
7을 세는데, 이 필드를 넣으면 **그 7이 그대로인 채 청구액만 오릅니다.**
문턱이 서 있는 이유("요청이 아니라 구글 호출 수로 과금을 막습니다")가
여기서는 작동하지 않습니다.

### 무엇을 사는 것인가

직선거리 `distanceM` 대신 실제 소요시간을 얻습니다. 즉 "1.2km" 가 "도보
14분" 이 됩니다. 나쁘지 않은 값입니다. 그러나 추천 카드는 **고르는 자리**
이고, 고른 다음에 `RouteService` 가 실제 경로와 소요시간을 정확히 알려
줍니다. 고르기 전에 분 단위가 필요한 것은 아닙니다.

### 이것을 받으면 무엇이 값을 치르는가

가장 비싼 등급으로 넘어가면 `GoogleQuotaFilter` 의 문턱 값을 전부 다시
잡아야 합니다. 지금 숫자들은 "넉넉히" 잡혀 있는데, 그 넉넉함의 값이 달라지면
넉넉함이 아니라 헐거움이 됩니다. 카드에 "도보 14분" 을 얹으려고 문턱 전체를
다시 재는 것은 남는 장사가 아닙니다.

|---|---|
| 새 외부 의존 | 없음 |
| 구글 호출 | 0 증가 — **그래서 문제입니다** |
| 요금 등급 | **Enterprise → Enterprise + Atmosphere** |
| 서버 저장 | 0 |
| EAS 재빌드 | 필요 없음 |

## 15. 대화형 도우미에 여행을 맡기기 (MCP) — **반대**

### 이미 있는 것

자연어로 받는 길이 이미 있습니다. `RecommendService` + `recommend-sheet.tsx`
+ 온디바이스 `intent.ts`. Lambus 가 ChatGPT 로 하는 일의 상당 부분을 앱
안에서, 질의문을 밖으로 안 내보내고 합니다.

### 걸리는 것 둘

**"사람이 수락해야 바뀝니다"** (`trip/domain/RouteTidy.java`). 남의 AI
클라이언트가 우리 API 를 부르면, 수락 화면이 우리 것이 아닙니다. 모델이
"셋째 날을 이렇게 바꿨습니다" 라고 말하고 실제로 바꿔 버리는 것을 우리가
막을 자리가 없습니다. `RouteTidy` 가 제안 → 비교 → 수락 → 되돌리기로
세워 둔 것이 통째로 우회됩니다.

**인증이 새로 생깁니다.** 지금 문은 하나입니다 — `JwtAuthenticationFilter`
와 `SecurityConfig` 의 `/api/**`. 남의 클라이언트를 들이려면 그 옆에 문을
하나 더 내야 하고, 그것은 `GoogleQuotaFilter` 가 세는 "누구" 의 정의도
흔듭니다(`:99-112` — 사람 번호 아니면 접속한 곳).

### 이것을 받으면 무엇이 값을 치르는가

문이 하나라는 것입니다. 구글로 나가는 문도 하나고 들어오는 문도 하나인데,
들어오는 문을 늘리면 `TripAccessPolicy` 의 404 규칙을 두 군데서 지켜야
합니다.
