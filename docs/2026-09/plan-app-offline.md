# 앱에서도 안 터질 때 일정이 보인다 — `box()` 하나를 갈아 끼운다

> `verdict.md` 1번에서 **조건부 찬성**으로 받은 것의 실행 계획입니다.
> 아직 코드는 한 줄도 바뀌지 않았습니다.
>
> **2차입니다.** 네이티브 모듈이 붙으므로 EAS 재빌드가 필요하고,
> `plan-widget.md` 와 한 번에 묶어 굽습니다.

## 1. 하려는 것

웹에서는 됩니다. **앱에서는 하나도 안 담깁니다.**

`frontend/src/lib/keep.ts:46-53`:

```ts
/** 웹에만 있습니다. 앱에는 localStorage 가 없어 조용히 넘어갑니다. */
function box(): Storage | null {
  try {
    return typeof localStorage === 'undefined' ? null : localStorage;
  } catch {
    return null;
  }
}
```

React Native 에는 `localStorage` 가 없습니다. 그래서 `canKeep()`(`:41`)이
**앱에서 항상 false** 이고, `keepTrip`(`:75-79`)과 `keptTrip`(`:112-115`)이
곧바로 돌아 나옵니다.

결과는 이렇습니다. 지하철에서 앱을 열면 화면이 빕니다. 커밋 `5a89dad` 가
"지하철, 산속, 로밍이 끊긴 순간 — 정작 일정이 가장 필요한 자리가 그런
데인데 화면이 통째로 비었다" 고 적고 고친 문제가, **앱에서는 아직 그대로**
입니다.

조사에서 트리플의 같은 문제를 보았습니다 — "와이파이를 끄면 일정이 불러지지
않습니다."

## 2. 이미 있는 것

**`box()` 하나만 빠져 있습니다.** 나머지는 다 옳게 짜여 있습니다.

| 필요한 일 | 지금 어디에 있나 |
|---|---|
| 담고 꺼내기 | `keep.ts:75` `keepTrip` · `:108` `keptTrip` |
| 사람 번호를 열쇠에 | `keep.ts:66-72` `keyOf`·`mapKeyOf` |
| 로그아웃 때 지우기 | `keep.ts:170` `forgetTrips` ← `auth/auth-provider.tsx:55` 가 이미 부릅니다 |
| 자리 차면 그림부터 버리기 | `keep.ts:85-94` · `:198` `forgetOld` |
| 언제 것인지 밝히기 | `keep.ts:220` `keptAgo` ← `app/trip/[id].tsx:984` 가 이미 씁니다 |
| 저장해 둔 동안 고치지 못하게 | `app/trip/[id].tsx:984` 주변 |
| 화면에서 꺼내 쓰는 흐름 | `app/trip/[id].tsx:146,151,171,177,189,204` |
| 갈라 끼우는 관습 | `lib/here.ts`·`here.web.ts`, `lib/intent.ts`·`intent.web.ts`, `lib/print.ts`·`print.web.ts`, `components/trip-map.tsx`·`trip-map.web.tsx` |

**화면을 한 줄도 안 고칩니다.** `trip/[id].tsx` 는 이미 `canKeep()` 을 묻고
`keptTrip()` 을 꺼내 쓰게 되어 있습니다. 앱에서 그 둘이 참을 돌려주기
시작하면 저절로 돕니다.

## 3. 버리는 것

### 3.1 `keep.ts` 를 통째로 갈라 쓰기 — 버립니다

`keep.ts` / `keep.native.ts` 두 벌을 만들고 싶어지는데, 그러면 "자리 차면
그림부터 버린다" 같은 판단이 **두 곳에 복사**됩니다. 한쪽만 고치는 날이 오고,
그날 웹과 앱이 다르게 버립니다.

**갈리는 것은 `box()` 하나뿐입니다.** 그것만 따로 떼어 냅니다.

```
lib/box.ts       — 웹. localStorage 를 그대로 (지금 keep.ts:46-53)
lib/box.native.ts — 앱. 아래 3.2
lib/keep.ts      — 둘 다 씀. box() 를 import 로 바꾸는 것 외에 안 바뀜
```

`intent-prompt.ts` 가 이미 같은 모양입니다 — 프롬프트를 한 곳에 두고 웹·앱
두 파일이 가져다 씁니다. 그 파일 주석이 이유를 적어 두었습니다: "같은 문장을
두 곳에 적어 두면 한쪽만 고쳤을 때 폰과 브라우저가 다르게 답하기 시작하는데,
그건 찾기 아주 어려운 종류의 어긋남입니다."

### 3.2 비동기 저장소 — 되도록 버립니다

여기가 이 계획의 어려운 자리입니다. `keep.ts` 의 함수들은 **전부 동기**
입니다. `keptTrip()` 이 `useMemo` 안에서 곧바로 쓰이고(`trip/[id].tsx:151`),
`canKeep()` 이 조건문 안에서 쓰입니다(`:171`).

`@react-native-async-storage/async-storage` 는 비동기입니다. 그것을 쓰면
`keep.ts` 의 서명이 전부 `Promise` 가 되고, `trip/[id].tsx` 의 여섯 자리가
따라 바뀝니다. **그러면 "화면을 한 줄도 안 고친다" 가 무너집니다.**

그래서 **동기로 읽을 수 있는 것을 찾습니다.** `expo-sqlite` 의 동기 API
(`getFirstSync` 계열)가 후보입니다. 이것이 성립하는지가 §9 의 첫 물음이고,
**안 되면 이 계획을 다시 씁니다** — 비동기로 가는 것은 범위가 다른 일입니다.

### 3.3 동선 그림 담기 — 앱에서는 버립니다

웹은 `StaticMapService` 로 받은 한 장짜리 그림을 담습니다
(`keep.ts:133` `keepTripMap`, `trip/[id].tsx:177-189`). 웹 지도는 그릴 때마다
구글을 부르는 살아 있는 지도라서 필요했습니다.

**앱은 다릅니다.** `react-native-maps` 이고 타일은 OS 가 담습니다. 같은
그림을 또 받으면 `callsOf` 의 `/map` 에 1 을 헛되게 씁니다.

`box.native.ts` 는 그림 열쇠(`MAP_PREFIX`)에 대해 **쓰기를 받고 버립니다**...
아니, 그게 아니라 **`keepTripMap` 을 부르는 쪽이 이미 막고 있습니다** —
`trip/[id].tsx:171` 이 `!canKeep()` 이면 돌아 나갑니다. 앱에서 `canKeep()` 이
참이 되는 순간 그림도 받기 시작합니다.

그래서 **부르는 쪽에 조건을 하나 더 둡니다.** "담을 수 있는가" 와 "그림이
필요한가" 는 다른 물음입니다. `canKeep()` 옆에 `needsMapImage()` 같은 것을
두고, 웹에서만 참입니다.

### 3.4 오프라인에서 고치기 — 버립니다

지금 그대로 둡니다. 저장해 둔 것을 보는 동안은 고치지 못합니다
(`trip/[id].tsx:984`). 커밋 `5a89dad` 가 이유를 적었습니다 — "눌러 봐야
서버에 닿지 못해 되돌아가는데, 그러면 고쳐진 줄 알았다가 아닌 것을 나중에
알게 된다."

나중에 큐에 쌓아 두고 나중에 보내는 것을 하고 싶어질 텐데, 그건 판 충돌
(`Versioned.check`)을 앱에서 풀어야 하는 별개의 큰 일입니다.

### 3.5 오프라인 장소 DB — 버립니다

`docs/done/recommend.md` §3.2 가 이미 버린 것입니다. 이 계획은 **일정을 담는
것**이고 장소 DB 를 앱에 심는 것과 다릅니다. 그 문단을 근거로 이 계획을
막지 않지만, 반대로 이 계획을 근거로 장소 DB 를 다시 꺼내지도 않습니다.

## 8. 순서와 의존

1. **§9 의 첫 물음을 먼저 답합니다** — 동기로 읽는 앱 저장소가 있는가.
   없으면 여기서 멈추고 계획을 다시 씁니다.
2. `lib/box.ts` 로 `box()` 를 옮기고 `keep.ts` 를 `import` 로 고칩니다.
   **웹이 그대로 도는지 먼저 확인합니다** — 여기서 깨지면 이미 되던 것이
   망가진 것입니다.
3. `lib/box.native.ts`.
4. `needsMapImage()` 와 `trip/[id].tsx:171` 의 한 줄 (3.3).
5. `plan-widget.md` 와 묶어서 EAS 빌드.

2번과 3번 사이에 웹 확인을 반드시 끼웁니다. 둘을 한꺼번에 하면 웹이 깨졌을
때 어느 쪽 때문인지 모릅니다.

## 9. 아직 모르는 것

- **동기로 읽는 앱 저장소가 있는가.** 이 계획 전체가 여기에 달렸습니다.
  `expo-sqlite` 의 동기 API 가 후보인데, Expo 57 / RN 0.86.3 의 새 아키텍처
  에서 되는지 확인 못 했습니다. 안 되면 `keep.ts` 를 비동기로 바꿔야 하고,
  그러면 `trip/[id].tsx` 의 여섯 자리가 따라 바뀌므로 **범위가 다른 계획**
  입니다.
- **앱의 저장 한도.** `forgetOld`(`keep.ts:198`)가 "브라우저의 저장 자리는
  5MB 남짓" 을 전제로 절반을 버립니다(`:212`). 앱은 한도가 훨씬 크므로 이
  절반 버리기가 과할 수 있습니다. 다만 **고치지 않는 편이 낫습니다** —
  웹과 앱이 다르게 버리기 시작하면 3.1 에서 피하려던 것이 됩니다.
- **`keptTripMap` 을 앱에서 어떻게 할지.** 3.3 대로 안 담으면 앱에서
  `keptTripMap()` 은 늘 `null` 입니다. `trip/[id].tsx:204` 가 그때 무엇을
  그리는지 봐야 합니다 — 빈 자리가 남으면 그건 커밋 `c5ae757` 이 없애려던
  "회색 바탕과 한 줄짜리 안내" 입니다.
- **앱이 실제로 쓰이는 비중.** README 는 실제 서비스가 nginx 가 내보내는 웹
  빌드라고 적습니다. 앱을 쓰는 사람이 거의 없으면 이 계획과
  `plan-widget.md` 는 3차 뒤로 가야 합니다. **이것을 먼저 알아야 2차를
  시작할지 정할 수 있습니다.**
