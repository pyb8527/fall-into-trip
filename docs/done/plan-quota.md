## 1. 하려는 것

오늘 처음 검색해도 "장소를 너무 자주 찾았습니다" 가 납니다.

재 본 결과입니다. **이 서버에는 구글 키가 없어서 구글이 한 번도 안
불립니다.**

```
갓 가입한 계정. 아직 아무것도 안 했습니다.

첫 검색               → 400  장소 검색이 꺼져 있습니다 (키 없음)
없는 날짜 영업시간    → 13번째에 429   ← 전부 404 나는 주소입니다
그다음 검색           → 429  장소를 너무 자주 찾았습니다
```

**존재하지 않는 날짜에 열세 번 요청했더니 한도가 바닥났습니다.** 컨트롤러는
404만 냈고 구글은 한 번도 안 불렸습니다.

우회할 방법이 지금은 서버를 다시 띄우는 것뿐입니다 — 카운터가 메모리에만
있어서 `docker compose restart api` 로 비워집니다. 쓰는 사람이 할 수 있는
일이 아닙니다.

## 2. 원인 넷

### 2.1 부를 것 "같은" 횟수를 미리 뺍니다

`GoogleQuotaFilter.callsOf` 가 **경로 문자열만** 보고 12·7·3·1 을 뺍니다.
필터는 컨트롤러 앞에 서 있어서 그 뒤에 무슨 일이 있을지 모릅니다 —
404 가 나든, 캐시에 맞아 구글을 안 부르든, 키가 없어 꺼져 있든 똑같이
뺍니다.

### 2.2 추정치가 양쪽으로 틀렸습니다

| 자리 | 지금 빼는 값 | 실제 |
|---|---|---|
| `/places-info` | 12 | 그 날 장소 수(최대 12). `PlaceInfoService:54` 가 **1시간 캐시**라 두 번째부터 0 |
| `/route/compare` | **3** | 구간 최대 12 × 수단 3 = **최대 36** (`RouteService:172,180`) |
| `/route`·`/info`·`/map` | 1 | 맞습니다. 다만 `StaticMapService`·`RouteService` 캐시에 맞으면 0 |
| `/api/places/search` | 1 | 맞습니다 |

일정을 짜는 동안 하루를 펼칠 때마다 15가 빠집니다. 장소를 하나 고치면
`daySeq` 가 바뀌어 둘 다 다시 부르니 또 15. **150을 열 번 만에 씁니다.**
반대로 정말 비싼 `compare` 는 12배 적게 셉니다.

### 2.3 막힌 요청도 계속 쌓습니다

```java
return counter.used.addAndGet(calls) <= limit;   // GoogleQuota.take
```

넘은 뒤에도 더합니다. 한 번 걸리고 나서 새로고침할수록 더 깊이 들어가고,
창이 끝날 때까지 안 풀립니다.

덤으로 `spend` 가 시간·하루 둘 다 무조건 뺍니다 — 시간에서 막혀도 하루치가
같이 닳습니다.

### 2.4 "하루" 가 달력이 아닙니다

`GoogleQuota:79` 가 `now.plus(Duration.ofDays(1))` 로 창을 엽니다. **첫
사용 시각부터 구르는 24시간**입니다. 어제 저녁에 썼으면 오늘 아침이 아직
그 창 안입니다. "오늘 처음인데" 가 여기서 나옵니다.

## 3. 버리는 것

### 3.1 추정표를 더 정확하게 고치는 것 — 버립니다

`/places-info` 를 12 대신 "그 날 장소 수" 로 고치는 길이 있습니다. 그래도
**캐시에 맞았는지는 여전히 모릅니다.** 필터가 서 있는 자리에서는 알 수
없는 값이라, 표를 아무리 다듬어도 2.1 이 남습니다.

### 3.2 필터를 없애는 것 — 버립니다

세는 일을 서비스로 옮기면 필터가 필요 없어 보입니다. 그런데 필터가 하는
일이 하나 더 있습니다 — **이미 바닥난 사람을 일을 시작하기 전에 돌려보내는
것.** 화면 하나가 잘못 만들어져 고리를 돌 때, 그 고리를 DB 조회 앞에서
끊는 자리입니다. 남깁니다.

### 3.3 한도를 올리는 것 — 이번에는 안 합니다

정직하게 세면 값이 어떻게 움직이는지 아직 모릅니다. 헛것이 빠지는 만큼
줄고, `compare` 가 정직해지는 만큼 늡니다. **재 보고 정합니다** — 숫자를
먼저 바꾸면 무엇 때문에 달라졌는지 알 수 없습니다.

### 3.4 시간대를 여기서 고치는 것 — 따로 냅니다

§9 에 적었습니다. 이 계획보다 넓은 문제이고, 고치면 알림 시각이 바뀝니다.

## 4. 갈 곳

```
[요청이 들어온다]
      |
      v
GoogleQuotaFilter
   · 이 자리가 구글을 부를 수 있는 자리인가?  (touchesGoogle)
   · 그렇다면 이 사람 몫이 남았는가?          (quota.left)   ← 보기만 합니다
      |
      +-- 안 남았으면 → 429. 아무 일도 안 하고 돌려보냅니다
      |
      v
컨트롤러 → 서비스
      |
      +-- 캐시에 있나?  → 있으면 그대로 돌려줍니다. 쿼터 안 씁니다
      |
      +-- 없으면 → quota.spend(who, 1) → 구글을 부릅니다
```

한 요청이 한도를 조금 넘겨 끝날 수 있습니다. 구간 열둘짜리 하루를 펼치면
한 번에 36을 씁니다. **중간에 끊어 반쪽짜리 응답을 주는 것보다 낫습니다** —
그러면 사람은 "왜 어떤 구간만 비었지" 를 묻게 됩니다. 다음 요청이 막힙니다.

### 5.1 누구인지를 어떻게 아는가

지금은 필터가 `HttpServletRequest` 에서 꺼냅니다. 서비스는 그것을 안
들고 있습니다.

서비스 서명에 `AuthPrincipal` 을 새로 넣지 않습니다 — `StaticMapService` 는
로그인 없이도 불리고(글의 동선 그림), 넷 중 셋은 이미 다른 이유로 서명이
깁니다. 대신 `RequestContextHolder` 에서 꺼내는 작은 자리를 하나 둡니다.

요청 밖에서 불리면(예약 작업 같은 것) `null` 입니다. 그때는 **세지 않고
통과**시킵니다 — 사람이 누른 것이 아니라 우리가 돌린 것이고, 그것을 누구
몫으로 달 수가 없습니다.

## 7. 테스트

`backend/src/test/http/quota.test.mjs` 를 새로 만듭니다. 구글 키가 없는
판에서 도는 것이 오히려 유리합니다 — **구글을 한 번도 안 부르는데 쿼터가
닳는가** 가 이 묶음이 보려는 것이기 때문입니다.

| 무엇을 | 몇 |
|---|---|

| 사람마다 따로 센다 | 1 |

첫째가 이 고장 그대로입니다. 지금 코드로는 **반드시 실패합니다** — 고치기
전에 한 번 돌려 빨간불을 보고 갑니다.

키가 있는 판에서만 볼 수 있는 것(캐시 미스일 때만 센다)은 **테스트로 못
잡습니다.** §9 에 적었습니다.

## 8. 순서와 의존

1. `quota.test.mjs` 를 먼저 씁니다. **빨간불을 보고 갑니다** — 안 그러면
   무엇을 고쳤는지 알 수 없습니다.
2. `GoogleQuotaKey` — 누구인지 꺼내는 자리.
3. `GoogleQuota` — `left()`, 넘으면 도로 빼기, 달력 창.
4. `GoogleQuotaFilter` — `touchesGoogle` 로 바꾸고 빼는 일을 뺍니다.
   **여기까지 하면 2.1·2.3·2.4 가 고쳐지고 테스트가 초록불이 됩니다.**
5. 네 서비스에 세는 줄. 하나씩 넣습니다.
6. 전체 테스트 묶음을 다시 돌립니다 — 쿼터는 모든 요청 앞에 서 있어서,
   잘못 세면 엉뚱한 묶음이 429 로 깨집니다.

4번과 5번 사이에 **쿼터가 아무것도 안 세는 구간**이 잠깐 생깁니다. 한
커밋 안에서 끝냅니다.

## 9. 아직 모르는 것

- **정직하게 세면 실제로 얼마나 쓰는가.** 150/700 을 그대로 둡니다. 헛것이
  빠지는 만큼 줄고 `compare` 가 정직해지는 만큼 느는데, 어느 쪽이 큰지는
  키가 있는 판에서 며칠 굴려 봐야 압니다.
- **캐시 미스일 때만 센다는 것을 어떻게 지키는가.** 구글 키가 없는 판에서는
  캐시에 닿기 전에 빠져나가는 자리가 많아 테스트로 못 잡습니다. 지금은
  네 파일을 눈으로 지킵니다. 다섯 번째가 생기면 빠뜨릴 자리입니다.
- **서버 시간대가 UTC 입니다.** `fit-api` 컨테이너에 `TZ` 가 없어
  `date` 가 UTC 로 나옵니다. 그래서 달력 창의 "하루" 도 UTC 기준이 됩니다.
  이 계획은 저장소의 기존 방식(`LocalDate.now()`)을 그대로 따릅니다 —
  여기만 다른 시간대를 쓰면 규칙이 둘이 됩니다.

  **다만 이것은 이 계획보다 넓은 문제입니다.** 같은 이유로
  `TripReminder:53` 의 `cron = "0 0 20 * * *"` 이 **20:00 UTC = 05:00 KST**
  에 돕니다. 주석은 "전날 저녁 여덟 시" 라고 적혀 있습니다. 새벽 다섯 시에
  알림이 갑니다. `PostView` 의 "하루 한 번" 도 오전 아홉 시에 넘어갑니다.

  고치는 것은 compose 에 `TZ=Asia/Seoul` 한 줄입니다. 알림 시각이 바뀌므로
  따로 냅니다.

  **2026-09-11 에 넣었습니다.** `docker-compose.yml` 의 세 서비스와
  `.env.example`. Alpine 이라 `tzdata` 가 있어야 먹는데, 이미지를 직접
  돌려 확인했습니다 — `TZ` 없이는 JVM 이 `GMT` 로 04:58, 넣으면
  `Asia/Seoul` 로 13:58 입니다.

### 잰 것

고치기 **전에** 테스트를 먼저 돌려 빨간불 셋을 봤습니다.

```

그다음 검색           → 429
```

- **시간대는 따로입니다**(§9). `TZ=Asia/Seoul` 한 줄인데 알림 시각이
  바뀌므로 이 계획에 섞지 않았습니다.
