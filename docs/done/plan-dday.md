## 1. 하려는 것

여행 목록을 열면 `D-51` 이 보입니다. 그런데 **홈에서는 안 보입니다.**
앱을 열면 메뉴 카드 넷이 있고, 남은 날을 보려면 「내 여행」 을 한 번 더
눌러야 합니다.

사람들은 여행 전에 날짜를 셉니다. 앱이 없어도 하는 행동입니다. 그 답이
첫 화면에 있으면 그 자체가 열어 볼 이유가 되는데, 지금은 한 단 들어가야
합니다.

## 2. 이미 있는 것

|---|---|

| `D-51`·`여행 중`·`내일` 로 말하기 | `src/app/(app)/trips.tsx:326` `countdownOf` |

**서버는 아무것도 안 바뀝니다.** 홈이 이미 받아 놓고 개수가 0인지만 보고
버리던 응답을, 한 번 더 읽습니다.

## 3. 버리는 것

### 3.1 여행 목록의 D-day 를 다시 만드는 것 — 버립니다

`ideas.md` 는 "홈과 여행 목록에 한 줄 얹는 일" 이라고 적었지만, 목록
쪽은 이미 서 있습니다. 손대지 않습니다.

### 3.2 여러 여행을 한꺼번에 보여 주는 것 — 버립니다

가장 가까운 **하나만** 답니다. 둘 이상을 세로로 늘어놓으면 그것은 목록
이고, 목록은 「내 여행」 이 이미 하는 일입니다. 홈에 목록을 또 만들면
같은 것을 두 자리에서 고치게 됩니다.

### 3.3 `D+40` — 버립니다

다녀온 여행에는 안 붙입니다. `trips.tsx:324` 의 판단을 그대로 따릅니다.

### 3.4 날짜 없는 여행 — 뺍니다

아직 짜는 중인 것입니다. 셀 날이 없습니다.

## 5. 닿는 파일

| 파일 | 무엇을 |
|---|---|
| `frontend/src/lib/countdown.ts` | 새로 만듭니다. `trips.tsx` 의 셈을 옮겨 옵니다 |
| `frontend/src/app/(app)/trips.tsx` | `daysBetween`·`countdownOf` 의 셈을 lib 에서 가져다 씁니다. 뱃지를 그리는 일은 그대로 둡니다 |
| `frontend/src/app/(app)/home.tsx` | 줄 하나를 더합니다 |

### 5.1 왜 lib 으로 빼는가

같은 셈을 홈과 목록이 각각 들고 있으면, "내일" 의 경계나 "여행 중" 의
판단을 한쪽만 고치는 날이 옵니다. 돈을 읽는 코드를 `lib/money.ts` 로
모은 것과 같은 이유입니다.

빼는 것은 **셈뿐**입니다. `{ kind: 'going' | 'tomorrow' | 'left', days }`
같은 값만 돌려주고, 뱃지로 그릴지 한 줄로 적을지는 부르는 쪽이 정합니다.
`countdownOf` 는 지금 JSX(`<Badge>`)를 돌려주는데, 홈은 뱃지 모양이 아닌
자리라 그대로는 못 씁니다.

### 5.2 곁다리 — `todayIso` 가 네 벌입니다

| 자리 | 이름 |
|---|---|
| `src/app/(app)/trips.tsx:392` | `todayIso` |
| `src/app/travel/[id].tsx:563` | `todayIso` |
| `src/app/trip/[id].tsx:2403` | `todayIso` |
| `src/app/community/[id].tsx:626` | `today` |

넷이 같은 일을 합니다. `lib/countdown.ts` 를 만드는 김에 여기로 모읍니다
— 다만 **이번에 손대는 두 화면만** 옮깁니다. 나머지 둘은 이 작업과
상관이 없어서, 같이 옮기면 이 변경에서 무엇을 봤는지가 흐려집니다.

## 6. 붙는 자리

홈의 **메뉴 카드 아래**입니다. 위가 아닙니다.

`home.tsx:114` 의 주석에 그 이유가 이미 적혀 있습니다 — 위에 두면 목록을
받아 온 순간 메뉴가 아래로 밀려 내려가, 이미 손이 가 있던 카드가
달아납니다. 남은 날도 서버에서 와야 아는 값이라 똑같습니다.

`FirstSteps` 와 **같은 자리, 배타**입니다. 여행이 0개면 `FirstSteps`,
다가올 여행이 있으면 이 줄, 다녀온 것만 있으면 둘 다 없습니다.

### API

없습니다. `GET /api/trips` 를 그대로 씁니다. 새 엔드포인트도, 권한
변경도, 스키마 변경도 없습니다.

### 구글 호출

## 7. 테스트

**HTTP 테스트에 더할 것이 없습니다.** 서버가 안 바뀝니다.

프런트는 `npm run typecheck` 과 `npm run export:web` 으로 봅니다. 셈
자체는 `lib/countdown.ts` 로 빠지므로 경계값을 눈으로 확인합니다.

| 경우 | 기대 |

| 어제 시작·내일 끝 | 여행 중 |
| 내일 시작 | 내일 |
| 모레 시작 | D-1 |
| 어제 끝 | 아무것도 없음 |
| `startIso` 없음 | 아무것도 없음 |
| 여행 0개 | FirstSteps 만 |
| 다녀온 것만 있음 | 둘 다 없음 |

`trips.tsx` 를 고치므로 **목록 화면이 그대로인지도 봐야 합니다** —
`D-51`·`여행 중`·`내일` 이 전과 같은 자리에 같은 색으로 뜨는지.

## 8. 순서와 의존

1. `lib/countdown.ts` — 셈과 `todayIso` 를 옮깁니다
2. `trips.tsx` — lib 을 쓰게 고칩니다. 화면은 그대로여야 합니다
3. `home.tsx` — 줄 하나를 더합니다
4. typecheck · export:web · 목록 화면 눈으로 확인

2 가 끝나기 전에 3 을 하지 않습니다. 목록이 전과 같은지 먼저 보고
나서야, 홈에서 이상한 값이 나왔을 때 어느 쪽 탓인지 압니다.

## 9. 아직 모르는 것

- **여행 중일 때 며칠째인지도 적을지.** 목록은 「여행 중」 으로만
  말합니다. 홈에서 「2일차」 까지 적으면 쓸모가 있을지, 아니면 목록과
  달라서 헷갈릴지 — 붙여 놓고 봐야 압니다. 1차는 목록과 같은 말만
  씁니다.

### 구현하며 답이 난 것

- **누르면 어디로 갈지 → `/trip/{id}` 로 보내면 됩니다.** 일정 화면이
  이미 여행 기간이면 오늘 날짜를 펼쳐 줍니다
  (`trip/[id].tsx:333-342`, `jumped`). 홈에서 따로 넘길 것이 없습니다.
- **날짜 없는 여행은 실제로 못 만듭니다.** `POST /api/trips` 가
  `시작일을 넣어 주세요` 로 400 을 답합니다. 타입이 `string | null` 이고
  `byWhen` 도 그 경우를 다루므로 막는 코드는 그대로 두었지만, 화면으로는
  만들 수 없는 상태입니다.

## 10. 무엇을 확인했나

`lib/countdown.ts` 로 셈을 옮긴 뒤 **목록이 전과 같은지** 먼저 봤습니다.
여덟 경우 전부 같습니다.

| 시작 | 뱃지 |
|---|---|
| 어제 시작·내일 끝 | 여행 중 |
| 오늘 시작 | 여행 중 |
| 내일 | 내일 |
| 모레 | D-1 |
| 7일 뒤 | D-6 |
| 9일 뒤 | D-8 |
| 51일 뒤 | D-50 |
| 어제 끝 | (없음) |

`daysBetween` 이 `-1` 을 합니다 — "내일 시작" 이 0 이고, 그 자리에는
숫자 대신 「내일」 이 붙습니다. 옮기기 전과 같은 셈입니다.

홈은 네 경우를 봤습니다.

| 상태 | 홈에 뜨는 것 |
|---|---|
| 여행 중인 것이 있음 | 「지금 그 길 위 / … / 여행 중」 |
| 다가올 것만 있음 | 「다음 여행 / 가장 이른 것 / D-n」 |
| 다녀온 것만 있음 | 아무것도 없음 |
| 여행이 0개 | `FirstSteps` 만 |

**화면 그림으로는 못 남겼습니다.** 브라우저가 스크린샷 요청에 계속
응답하지 않아, DOM 의 글자를 읽어 확인했습니다.
