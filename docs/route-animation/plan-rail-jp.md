## 1. 하려는 것

**지금 안 되는 것**
- 구글 Routes API 는 일본 대중교통 경로를 안 줍니다(`trip/application/RouteService.java:279`).
- 그래서 「이동 시간」으로 길을 찾아도 전철 구간에는 선이 없고, 여행 상세 3D 의 기차가 **긴자에서 시부야까지 빌딩 위로 곧게** 갑니다(`lib/journey.web.ts:360` `routeOf` → 선이 없으면 곧게).

**지금 사람이 어떻게 우회하나**
- 이동 칸에 "긴자선 · 16분"을 적습니다(`Move.via` · `Move.min`). 글로는 남지만 지도 위 움직임은 그대로 곧습니다.

- 2020년판 이후: "適用する利用規約に基づく(オープンデータ)". **이 규약이 무엇인지 확인 못 함.**

## 4. 버리는 것

- **시각 · 운임 · 환승 안내** — 시각표가 없습니다. 분은 사람이 적은 `Move.min` 만 씁니다.
- **실시간 열차 위치** (Mini Tokyo 3D 식) — ODPT 가 필요하고, 일부 노선은 재배포 제한이 있습니다.
- **버스 노선** — N02 에 없습니다. 버스 구간은 지금처럼(구글이 주면 그 선, 아니면 곧게).
- **`via` 를 풀어 읽기** — "긴자선 타고 시부야에서 갈아탐"을 해석하지 않습니다. **노선명과 글자가 정확히 같을 때만** 그 노선에 가산점을 줍니다(house-rules: 자유 글자를 읽지 않음).

## 6. 어느 구간을 노선으로 그리나

아래를 **모두** 만족할 때만입니다.

| 조건 | 왜 |
|---|---|
| 두 장소가 모두 일본 지역 상자 안 | 파일이 그 지역뿐입니다 |
| 구글 선(`option.polyline`)이 없다 | 있으면 그쪽이 정확합니다 |
| 적어 둔 수단이 `transit`, **또는** 안 적었고 탈것이 기차로 골라질 거리(`vehicleFor` 30km 초과) 이거나 2km 넘고 이 날 대중교통이 비었다(`noteFor` 가 말한 날) | 걷기 · 택시로 간 구간을 전철로 그리지 않으려고 |

탈것이 기차가 아니면(걷기 · 차) 노선 선을 주지 않습니다. 차가 철로 위를 달리면 안 됩니다.

## 10. 테스트

서버가 안 바뀌므로 HTTP 시험은 없습니다. 프런트에는 단위 시험 도구가 없으므로, 새 의존을 들이지 않고 **node 내장 시험**으로 `rail-graph.ts` 를 가공된 수도권 파일에 대고 돌립니다.

```bash
node --experimental-strip-types --test scripts/rail-jp/rail-graph.test.mjs
```

(타입만 벗겨 돌리므로 `rail-graph.ts` 에는 `enum` · `namespace` 같은 TS 전용 문법을 쓰지 않습니다. 개발 PC 의 node 판이 이 옵션을 받는지 확인 필요.)

| 무엇을 | 기대 |
|---|---|
| 긴자 → 시부야(같은 노선) | 노선 하나 `銀座線`, 선 끝이 두 장소에서 200m 안(`routeOf` 가 받아 줄 것) |
| 갈아타는 구간 | 노선 둘 이상, 갈아타기 간선이 한 번 |
| `via` 가 노선명과 정확히 같으면 그 노선을 고르는가 | 같은 거리의 두 길 중 그 노선 |
| `via` 가 엉뚱한 글자면 | 무시하고 최단 |
| 800m 안에 역이 없음 | `null` |
| 일본 밖 좌표 | `null`, 파일을 받지도 않음 |

화면 확인: 오사카 · 도쿄 여행 하나씩 만들어 3D 에서 전철 구간이 노선을 따라가는지, 걷기 · 택시 구간은 그대로인지.

`npm run typecheck`. 가공 스크립트는 같은 입력에 같은 출력을 내는지(두 번 돌려 비교).

## 12. 아직 모르는 것

- **2020년판 이후 이용 규약.** 이것이 시작 조건입니다.
- **가공한 파일 크기.** 수도권 하나가 몇 KB 인지 실측 전입니다. 300KB 를 넘으면 더 잘게(도쿄 23구 / 그 밖) 자릅니다.

- **"가까운 역" 800m** 는 짐작입니다. 도심은 넉넉하고 교외는 모자랄 수 있습니다.
