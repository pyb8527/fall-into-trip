# 길 위에서 동행자에게 물어본다 — 있는 투표로 가는 길을 낸다

> `verdict.md` 10번에서 **재설계 권장**으로 받은 것의 실행 계획입니다.
> 아직 코드는 한 줄도 바뀌지 않았습니다.
>
> **만드는 것은 투표가 아니라 길입니다.** 백엔드도 스키마도 안 건드립니다.

## 1. 하려는 것

여행 중에 "여기 말고 저기 갈까" 가 나옵니다. 지금 사람이 하는 일은 앱 밖에
있습니다 — 카톡으로 묻고, 정해지면 한 사람이 앱에 들어와 고칩니다.

**투표는 이미 있습니다.** `CandidateService` 와 `src/app/vote/[id].tsx`
입니다. 그런데 그것이 **떠나기 전 도구**로 서 있습니다.

| | 지금 |
|---|---|
| 후보를 올리는 길 | 보석함·추천·검색에서 "후보로 올리기" |
| 보는 곳 | `vote/[id].tsx` — 일정 화면과 **다른 화면** |
| 일정에서 가는 길 | 눈에 안 띕니다 |
| 일정에 이미 들어간 장소를 두고 묻는 길 | **없습니다** |

마지막이 이 계획입니다. 후보는 "넣을까" 를 묻는 자리인데, 여행 중에 나오는
물음은 **"이미 넣은 것을 뺄까"** 입니다.

조사한 앱들(Troupe·Limbo·AvoSquado·WePlanify)은 전부 떠나기 전 도구입니다.
Troupe 는 "정하고 나면 할 일이 끝난다" 고 스스로 적습니다.

## 2. 이미 있는 것

**서버는 손댈 것이 없습니다.**

| 필요한 일 | 지금 어디에 있나 |
|---|---|
| 후보 올리기 | `POST /api/trips/{tripId}/candidates` → `CandidateService.add:85` |
| 표 던지기 | `PUT /api/candidates/{candidateId}/vote` → `vote:124` |
| 후보 목록과 표 현황 | `GET /api/trips/{tripId}/candidates` → `listOf:42` · `Card`(`:223`) |
| 후보 내리기 | `DELETE /api/candidates/{candidateId}` → `remove:143` |
| **후보를 그날에 붓기** | `POST /api/days/{dayId}/places/from-candidates` → `pour:166` |
| 합의 기준 | 전원 동의. 표 안 던진 사람은 미정 |
| 투표 화면 | `src/app/vote/[id].tsx` |
| 소식 모으기 | `../done/plan-news.md` 의 소식함 (커밋 `39e2f14`) |

`pour`(`:166`)를 읽어 두었습니다. `access.requireCanEdit` 를 지나고, 없는
날짜에는 `notFound`, **다른 여행의 후보는 걸러 냅니다**(`:180-183` — "다른
여행의 후보를 섞어 보내는 것을 막습니다"). 여행 중에 불러도 되는 모양입니다.

## 3. 버리는 것

### 3.1 새 투표 장치 — 버립니다

조사에서 본 것들은 저마다 투표를 새로 만듭니다 — 순위 투표(Troupe), 봉인
투표(Limbo), 설치 없는 웹 투표지(Limbo), 코드 참여(AvoSquado).

**하나도 안 만듭니다.** `CandidateService` 의 전원 동의가 이미 서 있고,
그 기준을 흔들면 계획 단계에서도 무너집니다.

### 3.2 과반으로 낮추는 것 — 버립니다

"여행 중이라 급하니 과반으로" 가 솔깃합니다. 안 합니다. `house-rules` 의
**"합의는 전원 동의. 둘 다 로는 못 세고, 표 안 던진 사람은 미정으로
봅니다"** 가 그대로 적용됩니다.

급한 것은 **기다리는 시간**이지 기준이 아닙니다. 급하면 한 사람이 정하고
`updatedBy` 에 남기면 됩니다 — 그 길은 지금도 열려 있고, 소식함이 누가
고쳤는지 보여 줍니다.

### 3.3 계정 없이 참여시키는 것 — 버립니다

Limbo 의 "설치 없는 웹 투표지" 와 AvoSquado 의 "코드로 참여" 가 그것입니다.
`verdict.md` 12번에서 반대했고, `docs/ideas.md` 가 이미 같은 결론을
냈습니다 — **여행 안에 위치와 가계부가 있습니다.**

### 3.4 푸시 — 버립니다

표가 모였을 때 알림을 보내지 않습니다. `docs/ideas.md:44-45` 의 판단을
잇습니다 — 들어왔을 때만 보이면 알림 피로가 0입니다. **소식함으로
보냅니다.** 그 자리가 방금 생겼습니다(커밋 `39e2f14`).

### 3.5 "빼기" 를 후보로 만드는 것 — 버립니다

"이 장소를 뺄까요" 를 후보 테이블에 넣고 싶어지는데, 후보는 **넣을 곳**을
담는 자리입니다. 빼는 것을 거기 담으면 `pour` 가 그것을 일정에 넣습니다.

**대신 "바꿔 넣을 곳" 을 후보로 올립니다.** 물음이 "A 를 뺄까" 가 아니라
"A 대신 B 를 갈까" 가 되고, 그것은 지금 구조에 그대로 들어맞습니다.
전원이 B 에 찬성하면 `pour` 로 B 가 들어가고, A 는 사람이 뺍니다.

## 4. 갈 곳

```
[사람]  일정에서 장소 하나를 누릅니다
          |
          v
     "동행자에게 물어보기"
          |
          v
  recommend-sheet 또는 검색으로 대안을 고릅니다
          |          (plan-swap.md 와 같은 자리를 씁니다)
          v
  POST /api/trips/{tripId}/candidates     ← 지금 그대로
          |
          |  note 에 "오사카성 대신?" 을 적어 둡니다.
          |  무엇을 두고 묻는지가 후보 카드에 남아야 합니다
          v
  소식함에 한 줄 (커밋 39e2f14 의 자리)
          |
          v
[동행자]  일정 화면 위쪽에 "물어본 것 1" 이 보입니다
          |
          v
  PUT /api/candidates/{id}/vote            ← 지금 그대로
          |
          v
  전원이 찬성하면 카드가 "모두 찬성" 이 됩니다
          |
          v
[누구든]  "그날에 넣기"
          |
          v
  POST /api/days/{dayId}/places/from-candidates   ← 지금 그대로
          |
          v
  들어갑니다. 원래 장소는 사람이 뺍니다 (3.5)
```

**서버로 나가는 것이 넷인데 넷 다 이미 있습니다.**

## 6. API

넷 다 지금 그대로입니다. **새로 만들지 않습니다.**

| 무엇 | 경로 | 권한 |
|---|---|---|
| 후보 올리기 | `POST /api/trips/{tripId}/candidates` | `CandidateService.add:85` |
| 표 던지기 | `PUT /api/candidates/{candidateId}/vote` | `vote:124` |
| 후보 보기 | `GET /api/trips/{tripId}/candidates` | `listOf:42` |
| 그날에 넣기 | `POST /api/days/{dayId}/places/from-candidates` | `pour:166` — `requireCanEdit`, 없는 날짜에 404, 다른 여행 후보는 거름 |

**권한을 새로 열지 않습니다.** 이 계획이 하는 일은 이미 열려 있는 문으로
가는 길을 화면에 내는 것뿐입니다.

### 구글 호출

**`callsOf` 를 안 고칩니다.** 후보를 올리고 표를 던지는 것은 구글과 무관합니다.
대안을 고를 때 추천을 열면 그것은 이미 세고 있는 자리입니다.

### 스키마

**없습니다.** `TripCandidate` 에 `note` 가 이미 있습니다
(`CandidateService.Draft:213` 이 받습니다).

   먼저 더합니다.

2. `trip/[id].tsx` 위쪽에 "물어본 것 N". 누르면 `vote/[id].tsx` 로 갑니다.
3. 장소 줄에서 "동행자에게 물어보기" → 대안 고르기 → 후보로.
4. 소식함에 한 줄.

**`plan-swap.md` 와 3번에서 만납니다.** 둘 다 "일정의 장소 하나를 두고
대안을 고르는" 자리를 씁니다. 한쪽은 바로 바꾸고(혼자), 한쪽은 물어봅니다
(같이). **`plan-swap.md` 를 먼저 하는 편이 낫습니다** — 그 자리가 서고 나면
여기서는 단추 하나가 늘 뿐입니다.

## 9. 아직 모르는 것

- **`note` 가 얼마나 긴지.** `TripCandidate.note` 의 길이 제한을 안 봤습니다.
  "오사카성 대신?" 정도면 되겠지만 확인해야 합니다.
- **전원 동의를 여행 중에도 그대로 둘지.** 이 계획은 그대로 둡니다(3.2).
  그런데 실제로 길 위에서 한 사람이 폰을 안 보면 표가 영영 안 모입니다.
  그때 어떻게 하는지 — 기다리는지, 한 사람이 정하고 넘어가는지 — 는 써 보고
  정합니다. **기준을 낮추는 것 말고 다른 답이 있어야 합니다.**
- **"물어본 것 N" 을 어디까지 셀지.** 여행 중에 올린 것만인지, 떠나기 전에
  올려 둔 것까지인지. 후자면 여행 내내 숫자가 붙어 있어 무뎌집니다.
- **원래 장소를 자동으로 뺄지.** 3.5 는 "사람이 뺀다" 로 두었습니다.
  `pour` 가 넣기만 하고 빼지는 않으므로 그것이 자연스러운데, 둘 다 남아
  있는 상태를 사람이 못 알아챌 수 있습니다. 써 보고 정합니다.
- **`plan-swap.md` 와 단추가 둘이 되는 것.** 장소 줄에 "바꾸기" 와
  "물어보기" 가 나란히 서면 고르기 전에 한 번 멈추게 됩니다. 하나로 묶고
  안에서 갈라야 할 수도 있습니다 — 화면을 그려 보고 정합니다.
