# 못 가게 된 자리를 추천에서 고른 곳으로 바꾼다

> `verdict.md` 2번에서 **조건부 찬성**으로 받은 것의 실행 계획입니다.
> 아직 코드는 한 줄도 바뀌지 않았습니다.
>
> **백엔드를 한 줄도 안 건드립니다.** 구글 호출도 안 늘어납니다.

## 1. 하려는 것

비가 오거나 줄이 길어서 한 곳을 못 가게 됩니다. 지금 사람이 하는 일은
이렇습니다.

1. 일정에서 그 장소를 **지웁니다**
2. 추천이나 검색을 열어 다른 곳을 찾습니다
3. 담습니다 — **맨 뒤에 붙습니다**
4. 끌어서 원래 자리로 옮깁니다

그리고 지우는 순간 그 장소에 적어 둔 것이 같이 사라집니다 — 메모, 비용,
다녀옴 표시.

`recommend-sheet.tsx` 의 카드에 붙은 단추는 **담는 것**뿐입니다(`:211`
`keep` — 일정에 넣기·후보로 올리기·보석함에 담기). **"이 자리를 이것으로"**
가 없습니다.

## 2. 이미 있는 것

바꿔 넣을 것을 찾는 장치가 전부 있습니다.

| 필요한 일 | 지금 어디에 있나 |
|---|---|
| 지금 자리 기준으로 찾기 | `RecommendService` · `recommend-sheet.tsx:80,185-197` |
| "여기" 를 기준으로 고르기 | `recommend-sheet.tsx:298-312` |
| 그날 문을 여는지 | `RecommendService:149-153` |
| 이미 담은 곳인지 | `RecommendService.alreadyHave` |
| **장소를 통째로 고치기** | **`PlaceService.update`(`:93`)** — 이름·좌표·`placeId`·갈래까지 받습니다 |
| 고칠 때 판 검사 | `Versioned.check` |
| 화면에서 장소 고치기 | `components/place-form.tsx` |

**바꿔치기가 새 기능이 아닙니다.** `update` 가 이미 그 일을 할 수 있습니다.
`PlaceService:133` 주석이 그 범위를 넓게 잡아 두었습니다 — "날짜를 옮기는
것도 수정으로 봅니다."

없는 것은 **추천 카드에서 그 `update` 로 가는 길** 하나입니다.

## 3. 버리는 것

### 3.1 앱이 대안을 골라 주는 것 — 버립니다

조사에서 본 것은 "근처 대안으로 **바꿈**" 이고, 무엇을 기준으로 고르는지는
글에 없었습니다. 우리는 **고르지 않습니다.** 추천 목록을 띄우고 사람이
고릅니다.

"사람이 수락해야 바뀝니다" 이고, 실질적인 이유도 있습니다 — 못 가게 된 이유가
비인지 줄인지 예약 실패인지에 따라 대안이 완전히 다른데, 그것을 앱이 모릅니다.

### 3.2 검색을 새로 하는 것 — 버립니다

**이미 열려 있는 추천 목록에서만 고릅니다.** 바꾸기를 누를 때 구글을 다시
부르지 않습니다. 사람이 다른 것을 보고 싶으면 지금처럼 질의를 고쳐 다시
물으면 되고, 그것은 이미 세고 있는 자리입니다.

### 3.3 지우고 새로 담는 것 — 버립니다

지웠다 담으면 `sort` 가 맨 뒤로 가고, 그 장소에 붙어 있던 것이 사라집니다.
**한 줄을 제자리에서 고칩니다.**

### 3.4 메모·비용을 말없이 버리는 것 — 버립니다

바꾸면 이름·좌표·`placeId`·갈래가 새것이 됩니다. 그런데 **메모·비용·
다녀옴 표시**는 어느 쪽에 붙는 것인지 애매합니다.

- **메모·비용** — 사람이 적은 것입니다. 그대로 두되, **무엇이 남는지
  바꾸기 전에 보여 줍니다**(§4). 남겨 두면 "체크인 15시" 같은 것이 엉뚱한
  곳에 붙을 수 있으니, 지울지 말지도 그 자리에서 고르게 합니다.
- **다녀옴 표시** — 안 남깁니다. 다른 곳으로 바뀌었는데 다녀왔다고 둘 수
  없습니다. `Visit` 은 `placeId` 에 묶이므로 `VisitService.unmark` 를
  함께 부릅니다.

### 3.5 후보·보석함에서 바꾸는 것 — 이번에는 안 합니다

바꾸는 길은 **추천 카드** 하나로 둡니다. 보석함과 후보에서도 같은 것을
하고 싶어지는데, 그러면 같은 단추가 세 화면에 생깁니다. 추천에서 먼저 써
보고 정합니다.

## 4. 갈 곳

```
[사람]  일정에서 못 가게 된 장소를 누릅니다
          |
          v
     "다른 곳으로 바꾸기"
          |
          v
  recommend-sheet 가 열립니다
          |
          |  "여기" 기준 — 지금 있는 자리, 또는 그 장소 자리
          |  그날 문 여는지도 이미 봅니다
          v
  카드 목록. 카드마다 단추가 하나 늘어 있습니다
          |
          |  [일정에 넣기] [후보로] [보석함] [이 자리를 이것으로]
          |                                    ↑ 바꿀 대상이 있을 때만 보입니다
          v
     "이 자리를 이것으로" 를 누릅니다
          |
          v
  무엇이 바뀌고 무엇이 남는지 보여 줍니다
          |
          |  오사카성  →  덴포잔 대관람차
          |  메모 "9시 오픈런"  … 남길까요? 지울까요?
          |  비용 ¥600          … 남길까요? 지울까요?
          |  다녀옴 표시        … 지웁니다
          v
  [사람]  "바꾸기"
          |
          v
  PATCH /api/places/{id}      (지금 그대로)
  + DELETE /api/places/{id}/visit  (표시가 있었으면)
```

## 9. 아직 모르는 것

- **메모를 기본으로 남길지 지울지.** §3.4 를 "고르게 한다" 로 적었는데,
  고르라고 묻는 것 자체가 성가실 수 있습니다. 실제로 써 보고, 대부분
  한쪽으로 간다면 묻지 않고 그쪽으로 둡니다.
- **비용은 어떻게 할지.** `Place.costAmount`·`costCurrency` 가 커밋
  `70b0d8f` 로 생겼고, `654b4c1` 로 지출과 이어졌습니다. **장소에 붙은
  지출이 있으면** 바꾸기가 그 지출을 어디로 보내는지 안 정했습니다.
  `plan-place-cost.md` §8.2 가 "장소를 지우면 지출은 남긴다" 로 정했는데,
  바꾸는 것은 지우는 것과 다릅니다.
- **어느 자리 기준으로 추천할지.** 지금 있는 자리인지, 바꾸려는 장소의
  자리인지. 못 가게 된 곳 근처를 찾는 것이 맞을 때도 있고("근처 다른 데"),
  지금 자리가 맞을 때도 있습니다("여기서 가까운 데"). 둘 다 고를 수 있게
  할지 정해야 합니다.
- **바꾼 뒤 이동 시간.** 좌표가 바뀌면 앞뒤 구간이 달라집니다.
  `route/compare` 를 다시 받아야 하고, 그것은 구글 호출입니다. 지금
  화면이 장소를 고쳤을 때 어떻게 하는지 먼저 읽어야 합니다.
