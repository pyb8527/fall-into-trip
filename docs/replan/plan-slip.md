## 0. 왜 둘을 한 문서에 넣었나

계획은 하나씩 따로 쓰는 것이 규칙입니다. 여기서 어긴 이유를 적습니다.

둘 다 **같은 함수 두 개**를 고치는 일입니다 —
`minutesOfDay`(`trip/[id].tsx:2509`)와 `spareMinutes`(`:2517`). 4번(시각이
거꾸로면 말해 주기)은 `spareMinutes` 가 지금 뭉개고 있는 세 경우를 가르는
일이고, 1번(늦음이 뒤로 번지는 것)은 그 가른 결과 위에 섭니다.

따로 쓰면 같은 함수를 두 번 건드리게 되고, 먼저 간 쪽이 나중 것의 전제를
말없이 바꿉니다.

**4단계는 §8 의 1번부터 시작합니다** — 4번 쪽이 먼저입니다. 작고, 혼자서도
값이 있고, 1번의 전제가 됩니다.

## 1. 하려는 것

### 1.1 늦음이 구간 하나에서 멈춥니다

`GapBlock`(`trip/[id].tsx:2366`)이 구간마다 이렇게 셉니다.

```ts
const spare = spareMinutes(leaveAt, arriveBy);
const late = spare === null || chosen === null ? 0 : Math.round(chosen.seconds / 60) - spare;
```

`leaveAt` 은 이 장소에 적어 둔 시각, `arriveBy` 는 다음 장소에 적어 둔
시각입니다. 그 사이에 고른 수단으로 몇 분 늦는지가 `late` 입니다.

**그런데 그 늦음이 다음 구간으로 안 넘어갑니다.** 다음 구간은 자기
`leaveAt`(적어 둔 시각)에서 다시 셉니다. 실제로는 앞에서 20분 늦었으니
20분 늦게 출발하는데, 화면은 그것을 모릅니다.

사람이 지금 하는 우회: 첫 경고를 보고 **머릿속으로** 뒤를 다시 계산하거나,
장소마다 시각을 손으로 고칩니다.

### 1.2 시각이 거꾸로면 조용합니다

`spareMinutes`(`:2517`)가 셋을 한 답으로 뭉갭니다.

```ts
if (from === null || to === null || to < from) {
  return null;
}
```

| 경우 | 지금 | 맞나 |
|---|---|---|
| "점심때쯤" 처럼 못 읽음 | `null` → 아무 말 없음 | **맞습니다** |
| 다음 장소에 시각이 없음 | `null` → 아무 말 없음 | 맞습니다 |
| **14:00 다음에 13:00** | `null` → **아무 말 없음** | **틀렸습니다** |

세 번째는 **읽을 수 있었고, 읽었더니 말이 안 되는** 경우입니다. 손으로 끌어
옮기다 생기고, 지금은 조용히 지나갑니다.

## 2. 이미 있는 것

**새로 만들 것이 거의 없습니다.** 그래서 이 계획이 1차에 있습니다.

그 말이 이 계획 전체에 그대로 적용됩니다.

## 3. 버리는 것

### 3.1 단추 하나로 미는 것 — 버립니다

조사에서 본 것은 "늦음" 을 누르면 **바로 밀리는** 모양입니다. 안 합니다.

`RouteTidy` 가 세워 둔 순서가 **제안 → 비교 → 수락 → 되돌리기** 입니다.
`PlaceService.tidy`(`:176`)가 결과를 돌려주기만 하고 `reorder`(`:191`)가
사람이 수락했을 때 저장하는 것이 그 모양입니다.

**밀린 하루를 만들어 보여 주고, 수락해야 저장합니다.**

### 3.2 앱이 늦음을 스스로 판단하는 것 — 버립니다

"지금 시각이 10:50 이니 20분 늦었다" 를 앱이 정하지 않습니다. 사람이 아직
첫 장소에 있는지, 이미 출발했는지 우리는 모릅니다. 위치로 추정할 수도
있지만 그것은 자취를 보는 일이고, `LiveService` 가 일부러 안 하는 것입니다.

**사람이 "여기서부터 N분 늦었다" 를 정합니다.** 앱은 그 N 을 받아 뒤를 셉니다.

### 3.3 날짜를 가로질러 미는 것 — 버립니다

`verdict.md` 5번에서 반대했습니다. 하루 안에서만 밉니다. 밀어서 자정을
넘어가면 그 장소부터는 **밀지 않고 말만 합니다.**

### 3.4 저장을 잠그는 것 — 버립니다

4번 조사에서 본 것 중 하나는 충돌이 있으면 저장 단추를 잠급니다. 안 합니다.

"사람이 자유롭게 적은 칸을 숫자로 읽지 않습니다" 가 걸립니다. 시각 칸은
일부러 자유롭게 뒀고, 못 읽은 것을 충돌로 보면 멀쩡한 일정이 안 저장됩니다.
**보여만 줍니다.**

### 3.5 `Place.time` 을 시각 칸으로 바꾸는 것 — 버립니다

`HH:MM` 만 받게 하면 셈이 쉬워집니다. 안 합니다. "점심때쯤", "오픈런",
"체크인 후" 가 실제로 쓰이는 말이고, 그것을 막으면 이 앱이 계획을 짜는
도구로서 나빠집니다. `minutesOfDay` 가 걸러 내는 지금 방식이 옳습니다.

## 8. 순서와 의존

1. **`lib/clock.ts` 로 두 함수를 옮깁니다.** 옮기기만 하고 동작은 그대로
   둡니다. `typecheck` 로 확인합니다 — 여기서 깨지면 이미 되던 것이
   망가진 것입니다.
2. **거꾸로 적힌 경우를 가릅니다** (4번). `spareMinutes` 가 `null` 대신
   "못 읽음" 과 "거꾸로" 를 구분해 돌려주고, `GapBlock` 이 거꾸로일 때만
   한 줄 띄웁니다. **여기까지가 혼자서도 값이 있습니다.**
3. **`slipOf` 를 씁니다.** 하루와 구간들과 "N분 늦음" 을 받아 밀린 하루를
   돌려주는 순수 함수. 화면을 아직 안 건드립니다.
4. **밀린 하루를 보여 주는 판.** 전·후를 나란히, 닫는 시간을 넘는 줄에 표시.
5. **수락하면 저장.** `PATCH` 를 바뀐 것만큼.

2번과 3번 사이에 `typecheck` 를 끼웁니다. 1·2번은 3번 없이 됩니다.

## 9. 아직 모르는 것

- **얼마나 늦어야 물어볼지.** `RouteTidy.worthIt()` 은 200미터로 잡았습니다.
  시간은 몇 분인지 모릅니다. 5분이면 너무 자주 묻고, 30분이면 늦습니다.
  **실제로 써 보고 정합니다.**
- **밀린 시각을 저장하면 원래 계획이 사라집니다.** `Place.time` 을 덮어쓰면
  "원래 10:30 이었다" 가 없어집니다. 되돌리기를 어떻게 둘지 안 정했습니다 —
  칸을 하나 더 두는 것은 스키마가 바뀌는 일이라 이 계획 밖입니다.
- **"N분 늦음" 을 사람이 어떻게 넣을지.** 숫자를 치게 할지, `late` 값을
  그대로 쓸지, 5분 단위 칩을 줄지. 화면을 그려 보고 정합니다.
- **구간에 고른 수단이 없으면.** `chosenOf(gap)` 이 `null` 이면 `late` 가
  0 입니다. 그 구간은 못 미는데, 그때 뒤를 계속 밀지 말지 안 정했습니다.
- **`route/compare` 를 안 받아 온 하루.** 그 화면은 날짜를 펼쳤을 때만
  부릅니다(`DayExtrasController:42` 주석). 안 받았으면 밀 수가 없는데,
  그때 받아 오면 구글 호출이 늡니다. 지금은 **단추를 안 보여 주는 쪽**으로
  둘 생각이고, 실제로 써 보고 정합니다.
