# 무엇을 받고, 무엇을 고쳐 받고, 무엇을 버리는가 — 일정이 흐트러졌을 때

> `survey.md` 의 열둘을 코드에 비춰 본 기록입니다.
> 아직 코드는 한 줄도 바뀌지 않았습니다.
>
> 판단의 근거는 취향이 아니라 **이미 서 있는 규칙**입니다. 그런데 이번에는
> 근거의 절반이 **이미 짜여 있는 코드**였습니다 — 조사한 열둘 중 셋이
> 생각보다 훨씬 많이 들어가 있었습니다.

## 0. 먼저 — 조사할 때 몰랐던 것 둘

이 둘이 판정 여섯을 바꿉니다. `survey.md` 를 쓸 때는 못 봤고, 2단계에서
코드를 읽다 찾았습니다.

### 0.1 "몇 분 늦는지" 를 이미 셉니다

`survey.md` 는 `Place.time` 이 글자 칸이라 시각을 숫자로 못 읽는다고
적었습니다(`Place.java:68`). **그 문제는 이미 풀려 있습니다.**

`frontend/src/app/trip/[id].tsx:2509`:

```ts
/** "14:30" 을 자정부터의 분으로. 모양이 다르면 null 입니다. */
function minutesOfDay(at: string | null) {
  if (!at || !/^\d{2}:\d{2}$/.test(at)) {
    return null;
  }
  ...
}
```

**모양이 다르면 `null` 입니다.** "점심때쯤" 은 조용히 빠집니다. `house-rules`
의 "사람이 자유롭게 적은 칸을 숫자로 읽지 않습니다" 를 이미 지키는 방식이고,
그 위에 셈이 서 있습니다.

그리고 그 셈이 여기까지 가 있습니다(`:2393-2402`).

```ts
const spare = spareMinutes(leaveAt, arriveBy);
const late = spare === null || chosen === null ? 0 : Math.round(chosen.seconds / 60) - spare;
const rescue = late > 0 && spare !== null ? (가장 빠른 수단으로는 닿는지) : null;
```

**구간마다 "고른 수단으로 몇 분 늦는지" 와 "다른 수단으로는 닿는지" 를 이미
계산합니다.** 주석까지 정확합니다 — "시각을 안 적었거나 고른 수단이 없으면
맞춰 볼 것이 없습니다. 어느 수단 이야기인지 모르는 경고는 도움이 안 됩니다."

### 0.2 하루 합계도 이미 화면에 있습니다

`SheetHead`(`trip/[id].tsx`)가 판 맨 위에 늘 띄웁니다.

```
{done} / {total} 다녀옴        ← Visit 표시. 막대까지 있습니다
오늘 이동에 {asDuration(moving)}   ← 고른 수단들의 합
```

`moving` 은 `gaps` 의 각 구간에서 **사람이 고른 수단**의 시간을 더한 값입니다.
`RouteService.DayRoute` 의 `totalSeconds`(`:438`)는 `api/types.ts:314` 까지
내려오지만 **화면에서 아무도 안 씁니다** — 화면은 고른 수단으로 따로 셉니다.

### 0.3 그래서 남은 빈자리가 좁아졌습니다

조사에서 본 것 대부분이 이미 있습니다. 진짜로 없는 것은 셋입니다.

| 없는 것 | 왜 없는지 |
|---|---|
| **늦음이 뒤로 번지지 않습니다** | `late` 는 **구간 하나**의 값입니다. 첫 구간에서 20분 늦으면 뒤가 전부 밀리는데, 뒤 구간은 저마다 적힌 시각으로 다시 셉니다 |
| **밀린 뒤를 견줘 보여 주고 수락받는 자리가 없습니다** | `RouteTidy` 가 거리에 대해 그 모양(전·후·`worthIt()`)을 이미 하는데, 시간에는 그것이 없습니다 |
| **시각이 거꾸로면 조용합니다** | `spareMinutes` 가 `to < from` 일 때 `null` 을 돌려줍니다 — "못 읽음" 과 "거꾸로 적힘" 이 같은 답으로 뭉개집니다 |

## 1. "늦었다" 를 누르면 남은 일정이 밀린다 — **재설계 권장**

### 이미 있는 것

| 조사에서 본 단추 | 우리 쪽 |
|---|---|
| 끝냄 | **있음** — `VisitService.mark`(`:33`)·`unmark`(`:42`). `SheetHead` 가 "N / M 다녀옴" 으로 띄웁니다 |
| 건너뜀 | 없음. 다만 지우기(`PlaceService.delete:155`)가 있습니다 |
| **늦음** | **셈은 있고 번지지 않습니다** — 0.1 |
| 바꿈 | 아래 2번 |

### 걸리는 것 — 단추 하나로 미는 모양은 안 됩니다

MonkeyTravel 이 하는 것은 **누르면 밀리는** 것입니다. 그 모양이 이 저장소의
규칙과 맞지 않습니다.

`RouteTidy` 가 세워 둔 순서는 **제안 → 비교 → 수락 → 되돌리기** 입니다.
그리고 그 판단은 취향이 아니라 이 앱이 이미 치른 값입니다 —
`PlaceService.tidy`(`:176`)가 결과를 돌려주기만 하고,
`reorder`(`:191`)가 사람이 수락했을 때 따로 저장합니다.

`Tidied` 레코드가 그 모양을 그대로 보여 줍니다.

```java
public record Tidied(List<Place> order, double beforeMeters, double afterMeters) {
    public boolean worthIt() {
        return afterMeters < beforeMeters - 200;
    }
}
```

**전과 후를 함께 돌려주고**, "몇 미터 차이로 바꾸자고 물으면 성가십니다" 를
`worthIt()` 이 거릅니다.

### 고쳐 받는 모양 — 시간에 대해 같은 것을 세웁니다

단추를 눌러 미는 것이 아니라, **이미 계산하고 있는 `late` 를 뒤로 이어
붙여** 밀린 하루를 만들고, 지금 하루와 나란히 놓고 수락받습니다.

```
지금                      늦음을 반영하면
09:00 조식                09:00 조식
10:30 오사카성            10:50 오사카성   (+20)
13:00 점심                13:20 점심       (+20)
15:00 난바 (18:00 닫음)   15:20 난바
```

`RouteTidy` 가 거리에 대해 하는 일을 시간에 대해 하는 것이고, **새 관습이
아닙니다.**

### 값

| | |
|---|---|
| 새 외부 의존 | 없음 |
| 구글 호출 | **0 증가** — `gaps` 는 이미 받아 둔 것입니다 |
| 요금 등급 | 해당 없음 |
| 서버 저장 | 수락했을 때만. 기존 `PATCH /api/places/{id}` |
| EAS 재빌드 | **필요 없음** |
| 스키마 변경 | **없음** |
| 백엔드 변경 | **없음** |

### 지켜야 할 것

- **시각이 `HH:MM` 인 것만 밉니다.** "점심때쯤" 은 그대로 둡니다.
  `minutesOfDay` 가 이미 그렇게 걸러 냅니다.
- **`worthIt()` 에 해당하는 문턱을 둡니다.** 3분 밀린 것을 고치자고 묻는 것은
  성가십니다.
- **밀린 뒤에 문을 닫는지 다시 봅니다.** `PlaceInfoService` 가 그날 영업
  시간을 이미 알고, `PlaceHours` 가 화면에 있습니다(`trip/[id].tsx:2129`).
  밀어서 닫는 시간을 넘기면 그것을 말해 줘야 합니다 — 안 그러면 이 기능이
  "갔더니 닫힘" 을 만드는 쪽이 됩니다.

## 4. 시각이 겹치면 말해 주기 — **조건부 찬성**

### 막혀 있는 것

`spareMinutes`(`trip/[id].tsx:2517`)가 셋을 **한 답으로 뭉갭니다.**

```ts
if (from === null || to === null || to < from) {
  return null;
}
```

| 경우 | 지금 | 사람이 보는 것 |
|---|---|---|
| "점심때쯤" 처럼 못 읽음 | `null` | 아무 말 없음 — **옳습니다** |
| 뒤 장소에 시각이 없음 | `null` | 아무 말 없음 — 옳습니다 |
| **14:00 → 13:00 처럼 거꾸로** | `null` | **아무 말 없음** — 이건 틀렸습니다 |

세 번째는 **읽을 수 있었고, 읽었더니 말이 안 되는** 경우입니다. 앞 장소보다
뒤 장소가 이르게 적혀 있습니다. 손으로 끌어다 옮기다 생기는 일이고, 지금은
조용히 지나갑니다.

### 걸리는 것 — 저장을 잠그지 않습니다

조사에서 본 것 중 하나는 **충돌이 있으면 저장 단추를 잠급니다.** 안 합니다.

"사람이 자유롭게 적은 칸을 숫자로 읽지 않습니다" 가 걸립니다. 시각 칸은
일부러 자유롭게 뒀고, 못 읽은 것을 충돌로 보면 멀쩡한 일정이 안 저장됩니다.
`house-rules` 가 예로 든 것("빡빡하게", "숙소 빼고 5만")과 같은 종류의
사고입니다.

**보여만 줍니다.** 그리고 읽을 수 있었던 것만 말합니다.

## 5. 하나가 밀리면 뒤 **날짜**가 따라 밀림 — **반대**

### 이미 있는 것 — 그리고 그 선례가 반대 근거입니다

이 저장소에 연쇄가 하나 있습니다. `DayService:112-119` 의 `stayForward`
입니다. 숙소를 적으면 뒤 날들에도 채워 줍니다.

**그런데 조건이 붙어 있습니다.**

```java
if (later.getSort() > day.getSort() && later.getStayName() == null) {
```

**`stayName` 이 비어 있는 날만** 채웁니다. 커밋 `5a89dad` 가 그 이유를 적어
두었습니다 — "아직 잘 곳을 안 적은 날만 채웁니다. 옮겨 자는 날은 그대로
둡니다."

즉 이 앱의 연쇄는 **빈 곳을 채우는 것**이지 **적힌 것을 미는 것**이
아닙니다. 조사에서 본 cascade 는 반대로 이미 적힌 날짜들을 움직입니다.

### 이것을 받으면 값을 치르는 것

되돌리기입니다. 하나를 고쳤는데 열이 움직이면, 되돌리려면 열을 되돌려야
합니다. `RouteTidy` 는 하루 안에서만 움직이고 결과를 통째로 보여 주기
때문에 되돌릴 수 있습니다. 날짜를 가로질러 미는 것은 그 자리를 잃습니다.

그리고 **1번으로 대부분 됩니다.** 여행 중에 밀리는 것은 대개 **그날 안**
입니다. 하루를 통째로 미루는 것은 드물고, 그때는 사람이 날짜를 고치는 편이
빠릅니다.

| 덮는 범위 | 80곳·100곳입니다. 여행자가 갈 만한 곳의 아주 일부입니다 |
| 혼잡도 | 구글이 API 로 **안 팝니다**(`docs/during-trip/verdict.md` 9번) |

### 이것을 받으면 값을 치르는 것

"돈은 껄끄러움을 없애는 자리" 입니다. 동행자 넷 중 둘만 패스를 사면 그 자리에서
갈리고, 그 갈림을 만든 것이 우리 화면이 됩니다.

## 10. 길 위에서 다시 합의하기 — **재설계 권장**

### 이미 있는 것 — 새 투표 장치를 만들지 않습니다

조사에서 본 앱들은 투표 장치를 새로 만듭니다(순위 투표, 봉인 투표, 웹
투표지). **우리는 이미 있습니다.**

| 있는 것 | 어디에 |
|---|---|
| 후보 올리기 | `CandidateService.add`(`:85`) |
| 표 던지기 | `CandidateService.vote`(`:124`) |
| 후보를 그날에 붓기 | **`CandidateService.pour`(`:166`)** |
| 합의 기준 | 전원 동의. 표 안 던진 사람은 미정 |
| 화면 | `src/app/vote/[id].tsx` |

**`pour` 가 이 후보의 핵심입니다.** 고른 후보를 **어느 날에 넣는** 메서드이고,
여행 중에 "이거 대신 저기 갈까" 를 푸는 데 필요한 것이 정확히 그것입니다.

### 붙는 자리가 다릅니다

조사한 앱들은 **떠나기 전** 도구입니다. Troupe 는 "정하고 나면 할 일이
끝난다" 고 스스로 적습니다. 우리 것도 지금 그렇습니다 — 투표는 별도 화면
(`vote/[id].tsx`)에 있고, 여행 중에 보는 일정 화면에서 그리로 가는 길이
눈에 안 띕니다.

**만들 것은 투표가 아니라 길입니다.** 일정 화면에서 장소 하나를 두고 "동행자에게
물어보기" 를 누르면 그것이 후보가 되고, 모이면 `pour` 로 돌아옵니다.

### 값

| | |
|---|---|
| 새 외부 의존 | 없음 |
| 구글 호출 | 0 |
| 서버 저장 | 후보와 표. 이미 있는 테이블 |
| EAS 재빌드 | 필요 없음 |
| 스키마 변경 | **없음** |
| 백엔드 변경 | **없음일 가능성이 큽니다** — 아래 |

### 지켜야 할 것

- **전원 동의를 안 흔듭니다.** "둘 다" 로 못 세고, 표 안 던진 사람은
  미정입니다. 여행 중이라고 과반으로 낮추면 그 규칙이 계획 단계에서도
  무너집니다.
- **푸시를 늘리지 않습니다.** 소식함(`plan-news.md`)이 이미 "누가 무엇을
  했는지" 를 모읍니다. 표가 모인 것도 그리로 보냅니다.

## 11. 출발·도착 시각을 넣어 길을 묻기 — **조건부 찬성**

### 막혀 있는 것

`RouteService` 가 `computeRoutes` 를 부르면서 **시각을 안 보냅니다.** 그래서
지금 나오는 "지하철 23분" 은 **부른 그 순간** 기준입니다.

1번(밀린 하루)이 이것을 필요로 합니다. 20분 밀린 뒤의 이동 시간은 지금
시각의 것과 다를 수 있습니다 — 특히 대중교통은 배차가 있습니다.
주석 `:57` 이 이미 알고 있습니다: "대중교통은 시각에 따라 달라지므로 짧게
둡니다."

### 조건 둘

**(ㄱ) Routes API 요금 등급표를 먼저 봅니다.** 이것을 **세 번째로 못
봤습니다** — `docs/2026-09`, `docs/during-trip`, 그리고 이번입니다.
`departureTime` 을 넣는 것이 등급을 올리는지 모르면 값을 못 셉니다.

**(ㄴ) 1번 없이 혼자 하지 않습니다.** 시각을 넣을 이유가 1번뿐입니다.
지금 화면은 "지금 출발하면" 으로 충분합니다.

### 알아 둔 제약

| | |

## 12. 계정 없이 동행자가 같은 화면을 조작 — **반대**

### 두 곳에서 막힙니다

**하나 — 이미 반대로 결론 났습니다.** `docs/ideas.md` 가 "계정 없이 퀴즈만으로
동행자 자동 등록" 을 반대했고, 근거가 **"여행 안에 위치와 가계부가
있습니다"** 입니다. 그 근거는 지금 더 무거워졌습니다 — 장소 비용과 지출이
이어졌고(`docs/done/plan-place-cost.md`), 소식함이 누가 무엇을 했는지
남깁니다.

**둘 — 구조가 그렇게 서 있습니다.** `SecurityConfig` 가 비로그인으로 여는
것은 초대 미리보기, 글과 그 댓글·지도·카드, 장소 팁 읽기, 푸시 공개키뿐입니다.
**여행 자체는 하나도 안 열려 있습니다.** 열려 있는 것은 전부 **읽기**이고,
이 후보는 **쓰기**입니다.

### 이것을 받으면 값을 치르는 것

`TripAccessPolicy` 입니다. 지금 권한이 한 문으로 모여 있고 없는 것에는 404 로
답합니다. 계정 없는 사람에게 쓰기를 열면 그 문 옆에 다른 문이 생기고,
"누가 고쳤는지"(`updatedBy`)가 가리킬 사람이 없어집니다. 소식함이 방금
그 값 위에 섰습니다.

### 1차 — 재빌드도 서버 변경도 없는 것

**넷 다 백엔드를 한 줄도 안 건드립니다.** 이번 조사의 수확입니다 — 셈과

**없습니다.** 이번 조사에서 네이티브가 필요한 것이 하나도 안 나왔습니다.

| | 무엇 | 관문 |

**둘 다 계획을 아직 안 썼습니다.** 관문이 안 풀린 계획을 미리 쓰면, 관문

- **6 대체 항공편** — 월정액 바깥문을 열어서 얻는 것이 "목록 보여 주기"

- **7 Risk Alerts** — 같은 유료 바깥문 + 푸시 늘림 + **보상 연동이 돈 자리를

- **8 줄 서기·유료 패스** — 결제가 들어오고, 값이 오르내리는 것을 우리

- **12 계정 없이 조작** — `ideas.md` 가 이미 반대했고, `SecurityConfig` 가

## 아직 모르는 것

- **Routes API 요금 등급표.** 세 번째로 못 봤습니다. 11번의 값을 못 셉니다.
- **얼마나 늦어야 물어볼지.** `RouteTidy` 는 200미터로 잡았습니다
  (`worthIt()`). 시간은 몇 분인지 모릅니다 — 5분? 10분? 실제로 써 보고
  정합니다. `plan-slip.md` §9 에 두었습니다.
- **밀린 시각을 저장할지, 보여만 줄지.** 수락하면 `Place.time` 을 고치는
  것이 자연스러운데, 그러면 원래 계획한 시각이 사라집니다. 되돌리기를
  어떻게 둘지가 남습니다.
- **`pour` 가 여행 중에도 그대로 되는지.** `CandidateService.pour(me, dayId, ids)`
  의 권한과 전제를 아직 안 읽었습니다. 10번의 "백엔드 변경 없음" 이 여기에
  달렸습니다.
- **건너뜀을 어떻게 둘지.** 지우기는 있는데(`PlaceService.delete`), "오늘은
  안 갔지만 지우고 싶지는 않다" 를 표현할 자리가 없습니다. `Visit` 의 반대가
  필요한지, 아니면 그냥 안 누르면 되는지 안 정했습니다.
