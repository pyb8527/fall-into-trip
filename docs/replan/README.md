## 이번 조사에서 가장 쓸모 있었던 것

### 이미 셈이 다 되어 있었습니다

조사할 때는 `Place.time` 이 글자 칸이라(`Place.java:68`) 시각을 못 읽는다고
봤습니다. **2단계에서 코드를 읽어 보니 이미 풀려 있었습니다.**

| | 어디에 |
|---|---|
| `"14:30"` 을 분으로, 모양이 다르면 `null` | `trip/[id].tsx:2509` `minutesOfDay` |
| 두 시각 사이의 여유 | `:2517` `spareMinutes` |
| **구간마다 몇 분 늦는지** | `:2395` `late` |
| **다른 수단으로는 닿는지** | `:2399` `rescue` |
| 하루 이동 합계 | `SheetHead:1439` `moving` |
| 다녀옴 표시와 막대 | `VisitService` + `SheetHead` |

`house-rules` 의 "사람이 자유롭게 적은 칸을 숫자로 읽지 않습니다" 를
`minutesOfDay` 가 정규식 하나로 지키고, 그 위에 셈이 서 있습니다.
`GapBlock` 주석이 값까지 적어 두었습니다 — **"재는 데 드는 것이 없습니다.
두 시각도 이동 시간도 이미 받아 온 것이라 구글을 다시 부르지 않습니다."**

그래서 조사한 열둘 중 **3번(이동 시간과 하루 합계)은 이미 있음**으로
끝났고, Wanderlog 가 하는 것보다 많이 합니다.

### 남은 빈자리가 좁고 뚜렷합니다

| 없는 것 | |
|---|---|
| **늦음이 뒤로 안 번집니다** | `late` 는 구간 하나의 값입니다 |
| **밀린 뒤를 견줘 수락받는 자리가 없습니다** | `RouteTidy` 가 **거리**에 대해 그 모양을 이미 합니다 |
| **시각이 거꾸로면 조용합니다** | `spareMinutes` 가 "못 읽음" 과 "거꾸로" 를 뭉갭니다 |

### 1차 셋이 전부 백엔드를 안 건드립니다

계획 셋 다 **서버 0 · 스키마 0 · 구글 호출 0 · 새 의존 0 · 재빌드 0** 입니다.
`plan-revote.md` 는 서버로 나가는 것이 넷인데 **넷 다 이미 있습니다.**

## 무엇부터 하나

### 1차 — 재빌드도 서버 변경도 없음

| | 계획 | 왜 이 순서인가 |
|---|---|---|
| 1 | [`plan-slip.md`](plan-slip.md) §8 의 1~2 | 함수를 `lib/clock.ts` 로 옮기고 **거꾸로 적힌 시각**부터. 가장 작고 혼자서도 값이 있습니다 |
| 2 | [`plan-swap.md`](plan-swap.md) | `plan-revote.md` 가 이 자리를 씁니다 |
| 3 | [`plan-slip.md`](plan-slip.md) §8 의 3~5 | 밀린 하루를 만들고 수락받는 쪽 |
| 4 | [`plan-revote.md`](plan-revote.md) | 2번이 선 뒤에 하면 단추 하나가 늘 뿐입니다 |

`plan-swap.md` 와 `plan-revote.md` 는 **장소 하나를 두고 대안을 고르는 같은
자리**를 씁니다. 한쪽은 바로 바꾸고(혼자), 한쪽은 물어봅니다(같이).

### 2차 — EAS 재빌드

**없습니다.** 이번 조사에서 네이티브가 필요한 것이 하나도 안 나왔습니다.
앞선 두 조사와 다른 점입니다.

### 3차 — 서버 작업 (계획 아직 안 씀)

| | 무엇 | 관문 |
|---|---|---|
| 5 | 출발 시각을 넣은 경로 질의 (11번) | **Routes API 요금 등급표.** 그리고 `plan-slip.md` 가 먼저 |
| 6 | 비 오면 실내 대안 (9번) | **`docs/during-trip/verdict.md` 5번(날씨)이 먼저** |

**관문이 안 풀린 계획은 미리 쓰지 않았습니다.** 관문 너머가 달라지면 두 번
쓰게 됩니다.

## 하지 않기로 한 것

근거는 `verdict.md` 에 하나씩 적었습니다.

| 안 하는 것 | 한 줄 이유 |
|---|---|
| 날짜 단위 연쇄 밀림 | 이 앱의 연쇄(`stayForward`)는 **빈 곳을 채우는 것**이지 적힌 것을 미는 것이 아닙니다. 되돌리기를 잃습니다 |
| 대체 항공편 | 월정액 바깥문을 열어 얻는 것이 "목록 보여 주기" 입니다. TripIt 조차 예약은 안 해 줍니다 |
| Risk Alerts | 같은 유료 바깥문 + 푸시 늘림 + **보상 연동이 돈 자리를 새로 만듭니다** |
| 줄 서기·유료 패스 | 결제가 들어옵니다. 값이 오르내리는 것을 우리 화면에 적으면 우리가 매긴 값처럼 보입니다 |
| 계정 없이 동행자가 조작 | `ideas.md` 가 이미 반대했고, `SecurityConfig` 는 비로그인에 **읽기만** 엽니다. `updatedBy` 가 가리킬 사람이 없어집니다 |
| 저장을 잠그는 충돌 경고 | 자유롭게 적은 칸을 못 읽었다고 저장을 막으면 멀쩡한 일정이 안 저장됩니다 |
| `Place.time` 을 시각 칸으로 바꾸기 | "점심때쯤" 이 실제로 쓰이는 말입니다 |

## 조사에서 못 채운 자리

- **가장 중요한 앱을 파는 쪽 글로만 봤습니다.** 1·2·12번의 근거가
  MonkeyTravel 자기네 비교 글 하나입니다. 앱을 직접 안 써 봤고, "다른 일곱은
  아무도 안 한다" 는 결론은 옮기지 않았습니다.
- **레딧을 또 못 봤습니다.** 불평 축이 이번엔 특히 약합니다 — "일정이 밀려
  불편하다" 는 앞선 조사에서 **관찰로 적은 것**이지 사용자 글로 확인한 것이
  아닙니다.
- **Routes API 요금 등급표를 세 번째로 못 봤습니다.** `docs/2026-09`,
  `docs/during-trip`, 그리고 이번입니다.
