## 0단계 — 바로 반려되는 작은 것들

1. **iOS 카메라 크래시.** 웹뷰에서 사진 고르기(`lib/pick-photo.web.ts:177`)를 열면
   iOS 가 「사진 찍기」도 보여 주는데, `NSCameraUsageDescription` 이 없어
   누르는 순간 앱이 꺼집니다. 심사자가 누르면 그대로 반려입니다.
   → `app.json` 의 expo-image-picker 에 카메라 문구를 넣습니다(카메라를 쓰는
   이유: 「여행 사진을 바로 찍어 올리려고」).
2. **위치를 묻지도 않고 바로 묻는 문제.** `trip/[id].tsx:1253` 이
   `Platform.OS === 'web'` 이면 위치를 바로 켜는데, 앱 껍데기 안의 웹뷰도 web
   이라 여행 상세를 열자마자 OS 위치 창이 뜹니다. 바로 위 주석의 뜻(「앱에서는
   십자를 누를 때까지 묻지 않습니다」)과 반대입니다. → 껍데기 안(`inShell`)에서는
   자동으로 켜지 않습니다.
3. **빌드 설정.**
   - iOS: `ITSAppUsesNonExemptEncryption: false`(HTTPS 만 씀),
     `ios.privacyManifests`(쓰는 required-reason API 사유).
   - `supportsTablet` — 켜 두면 iPad 스크린샷과 iPad 심사가 따라옵니다. 끄기를
     권합니다(정할 것 ⑤).
   - Android: `blockedPermissions` 로 `READ_MEDIA_IMAGES` · `READ_MEDIA_VIDEO` ·
     `READ_EXTERNAL_STORAGE` 를 막습니다(구글은 시스템 사진 선택기만 허용).
     targetSdk 36(2026-08-31부터 필수) · 16KB 페이지 · edge-to-edge 는 빌드 결과로
     확인합니다.

## 1단계 — 회원 탈퇴

### 지금 상태

- 사용자가 스스로 지우는 길이 **없습니다**. 운영자 삭제(`AdminUserService.java:176`)만
  있고, 그마저 여행 주인이거나 지출 기록이 있으면 막힙니다.
- 막히는 까닭은 CASCADE 가 없는 외래키 넷입니다.
  `trips.owner_id`, `expenses.payer_id` · `created_by`, `groups.owner_id`,
  `trip_items.created_by`(V19). 나머지(사진 · 글 · 댓글 · 위치 · 소셜 연결 …)는
  CASCADE 로 함께 지워집니다.
- 디스크의 사진 파일은 지우지 않습니다(`PhotoStore.deleteIfExists` 는 사진 한 장
  지울 때만 씀).
- 구글 · 카카오 토큰은 저장하지 않습니다(`user_identities` 에 provider · subject ·
  email 만).

### 지우면 무엇이 어떻게 되나 (권하는 안)

| 데이터 | 처리 | 까닭 |
|---|---|---|
| 내가 주인인 여행 | 동행자가 있으면 **가장 먼저 들어온 동행자에게 넘김**, 혼자면 지움 | 친구들의 일정이 사라지면 안 됨 |
| 가계부 지출(낸 사람 · 적은 사람) | **「탈퇴한 사람」 자리표시 계정**으로 바꿈 | 남은 사람의 정산이 깨지면 안 됨. 이름 말고 개인정보 없음 |
| 장소 · 일정 항목의 「고친 사람」 | 「탈퇴한 사람」으로 | 같음 |
| 내가 주인인 모임 | 다음 사람에게 넘김, 혼자면 지움 | 여행과 같음 |
| 글 · 댓글 · 팁 · 피드 · 사진 · 별점 · 위치 · 깃발 | 지움(이미 CASCADE) + **디스크 사진 파일도 지움** | 「지체 없이, 복구할 수 없게」(개인정보보호법 21조) |
| 리프레시 토큰 | 모두 끊음 | 다른 기기 로그인도 즉시 끝 |
| 감사 기록(audit_log) | user_id 만 남김 | 부정 이용 대응. 처리방침에 보관 기간을 적음 |

- **바로 지움**을 권합니다(유예 기간 없음 — 정할 것 ②). 애플은 걸리는 기간을
  알려 주라고 하므로, 끝나면 「다 지웠어요」 화면으로 알립니다.

### 서버

- `DELETE /api/auth/me` — 비밀번호 사용자는 비밀번호 확인, 소셜 사용자는 **10분
  안에 다시 로그인**한 경우만(남이 잠깐 빌린 폰으로 지우지 못하게).
- `AccountDeletionService` 한 곳에서 한 트랜잭션으로:
  주인 넘기기 → 「탈퇴한 사람」으로 바꾸기 → 토큰 끊기 → 지울 사진 파일 목록
  모으기 → `users` 행 지우기(CASCADE) → **커밋된 뒤** 파일 지우기 → 감사 기록.
- Flyway V58: 「탈퇴한 사람」 계정 한 줄(로그인 불가) + 위 외래키 정리.
- 운영자 삭제(`AdminUserService.delete`)도 같은 서비스를 씁니다 — 지금 막히던
  두 경우가 함께 풀립니다.
- 소셜 연결 끊기
  - 구글: 저장한 토큰이 없어 끊을 것이 없습니다. 완료 화면에 「구글 계정 설정에서
    fit 권한도 지울 수 있어요」 안내.
  - 카카오: 연결 끊기 API 는 사용자 액세스 토큰이나 **Admin 키**가 필요합니다.
    Admin 키는 두지 않기로 했으므로, 탈퇴 직전 카카오로 다시 로그인할 때 받은
    토큰으로 끊습니다(정할 것 ④).
  - 애플: 4단계에서(토큰 폐기 필수).

### 앱 화면

- 설정 › 계정 › **회원 탈퇴**.
- 한 장에: 지워지는 것 / 남는 것(가계부에는 「탈퇴한 사람」으로) / 넘어가는 것

- 이 주소를 Play Console 「데이터 삭제」 항목에 적습니다.

## 2단계 — 약관 · 처리방침 · 동의 · 권한 안내

2. 개인정보처리방침 — 처리 목적 · 보유 기간 · 파기 · 위탁(구글 · 카카오 · 호스팅) ·
   권리 행사 · 보호책임자 · 쿠키(개인정보보호법 30조 항목).
3. 위치기반서비스 이용약관 — 위치정보법 18 · 19조 항목, 개인위치정보 처리방침 포함.

- 로그인 없이 보이는 `/terms` · `/privacy` · `/location-terms`(소개 페이지처럼
  `public/` 에 따로 둠). 앱 설정과 소개 페이지 바닥에 링크.

### 가입 · 기존 가입자

- 가입 화면: **만 14세 이상** 확인 + 필수 동의(약관 · 처리방침). 14세 미만은 받지
  않습니다(법정대리인 동의를 받는 것보다 간단).
- 기존 가입자: 다음 로그인 때 같은 동의를 한 번 받습니다.

### 위치

- 위치 약관은 **위치 기능을 처음 켤 때** 따로 동의받습니다.
- 「같이 보는 사람에게 내 위치 알리기」를 켤 때: 누구에게(이 여행 동행자 n명) ·
  무엇을 · 얼마나(4시간 뒤 꺼짐) 보이는지 보여 주고 동의받습니다. 위치정보법
  19조의 「제3자 제공 시 매번 즉시 통보」를 이 화면으로 갈음할 수 있는지는 확인이
  필요합니다(정할 것 ⑥).
- 만료된 위치 행을 그 여행을 열 때만 지우고 있습니다 → 매시간 지우는 작업을 둡니다.

### 앱 접근권한 안내 (정보통신망법 22조의2)

- 처음 실행할 때 한 장: 필수 권한 없음, 선택 권한 — 위치(내 위치 · 지금 여기 ·
  위치 알리기) · 사진(올리기) · 카메라(찍어 올리기) · 알림 · 캘린더. 거부해도

## 3단계 — 신고 · 차단 · 걸러내기 · 문의처

- **신고가 빠진 곳**: 피드 글(`FeedController` — 전체 공개가 있음), 프로필(이름 ·
  소개 · 사진). 여행기 · 댓글 · 팁처럼 3건이면 저절로 숨기고 운영 화면에 모읍니다.
- **차단**(지금 없음): `user_blocks(blocker, blocked)`. 차단하면 서로의 글 · 댓글 ·
  팁 · 피드가 안 보이고, 그 사람의 초대 링크로 들어오지 못합니다. 프로필 · 글 메뉴에
  「이 사람 차단」, 설정에 차단 목록.
- **걸러내기**: 욕설 목록으로 올릴 때 막기(글 · 댓글 · 팁 · 피드 · 프로필 이름 ·
  소개). 신고 자동 숨김과 함께 애플이 묻는 「걸러내는 방법」에 답이 됩니다.
- **문의처**: 설정 · 소개 페이지 · 스토어에 이메일 공개(주소는 정할 것 ⑦).

## 4단계 — Apple 로그인

- iOS 앱: `expo-apple-authentication`. 웹(PC · 안드로이드): Sign in with Apple JS
  (서비스 ID).
- 서버: 애플 identity token 검증(JWKS), `user_identities.provider = 'apple'`.
  「이메일 가리기」(relay 주소)를 그대로 받습니다.
- 탈퇴 때 **토큰 폐기 필수** → 로그인할 때 받은 authorization code 로 애플
  refresh token 을 받아 **암호화해 저장**해 두었다가 `/auth/revoke`.
- **서버-서버 알림 엔드포인트**(한국 개발자 필수): `/api/auth/apple/notifications` —
  사용자가 애플 쪽에서 연결을 끊거나 계정을 지우면 받습니다.
- 사람이 준비: Apple Developer 에서 Services ID · Sign in with Apple 키(.p8) ·
  Team ID → 서버 환경변수.
