## 0. 이번 조사가 어디서 시작하나

`docs/groups/` 가 그룹의 뼈대를 세웠습니다. 0~3단계(걷어 내기 · 그룹 · 피드 ·
여행기에 글 싣기)는 끝났고 4단계(리뷰 · 마이페이지 · 소식)가 남아 있습니다.
그래서 이번에는 **뼈대가 선 다음에 그 위에 무엇을 올릴까**를 봅니다.

다시 보지 않은 것:

- 밴드 · 카카오톡 오픈채팅 · 소모임/문토 — `docs/groups/survey.md` 4절에서 봤습니다
- 이미 "안 한다"로 끝난 것 — 채팅 · 공개 그룹 · 친구 · 그룹 회비 · 좋아요
  (`docs/groups/verdict.md`), 퀴즈 초대 · 내기·벌칙 · WebSocket (`docs/ideas.md`)

조사 중에 house-rules 의 한 줄이 지금 코드와 어긋나 있어 고쳤습니다.
"서버에 파일을 안 쌓습니다"는 2026-09-29 에 뒤집혔고 `photo/application/PhotoStore.java`
가 실제로 있습니다. 표를 "사진은 한 군데에, 한도 안에서"로 바꿨습니다.

## 1. 날짜 정하기 투표

**한 줄** — 후보 날짜마다 "돼요 / 어쩔 수 없으면 돼요 / 안 돼요"를 받고, 하나로 정하면 그 여행의 날짜가 됩니다.

**어느 불편에서** — P1, P2

**어떻게 동작하나**
만든 사람이 후보 날짜(또는 기간)를 몇 개 올리고 마감을 정합니다. 멤버는 칸마다 셋 중 하나를 고릅니다.
칸에는 "돼요"가 많을수록 진하게 칠해지고, 누르면 누가 어떻게 답했는지 보입니다.
만든 사람이 하나를 고르면 그 날짜가 여행에 들어가고, 각자의 답이 그대로 참석 응답이 됩니다(Partiful).

- 세 단계 중 "어쩔 수 없으면"은 Doodle 의 if-need-be 입니다. 칸을 두 번 누르면 노랗게 바뀝니다.
- When2meet 은 시간 격자를 끌어서 칠하고, 겹칠수록 진해집니다. 계정이 필요 없습니다.
- Howbout 은 캘린더를 연결해 모두 빈 날을 자동으로 찾습니다.
- 카카오톡은 글 하나에 투표를 세 건까지 넣고, 정한 날을 톡캘린더에 넣습니다.

**무엇을 요구하나**

| 항목 | |
|---|---|
| 위치 | 불필요 |
| 사진·파일 | 불필요 |
| 푸시 | 마감 · 확정 알림에 있으면 좋음 |
| 외부 API | 불필요 (Howbout 식 캘린더 연동만 필요) |
| 서버 저장 | 후보와 답 |

**출처**
- help.partiful.com/hc/en-us/articles/24467301043355 (공식, 2026-10-02 확인)
- help.doodle.com/en/articles/9457276 (공식 요약만 봄)
- timespree.app/blog/how-to-use-when2meet (2차)
- howbout.app/get-help/group-availability/ (공식 요약만 봄)
- hankyung.com/article/202407116037Y (카카오톡 투표, 2차)

**확인 못 한 것** — Let's Jetty 의 "스마트 날짜 추천"이 어떻게 동작하는지.

> house-rules: 「합의는 전원 동의」(`CandidateService`)와 성격이 다릅니다. 날짜는 겹치는 날을 고르는 일이라 득표로 정하게 됩니다.

## 2. 참석 응답 — 이번 여행에 누가 가나

**한 줄** — 그룹 여행마다 멤버가 "갈게요 / 못 가요 / 아직 몰라요"와 한 줄 메모를 답합니다.

**어느 불편에서** — P2, P9

**어떻게 동작하나**
여행을 만들면 멤버에게 응답을 묻습니다. 메모는 다른 사람에게도 보입니다(Apple Invites).
주최자가 응답에 질문을 붙일 수 있습니다. 알레르기처럼 남에게 안 보일 답은 주최자만 봅니다(Partiful).
Let's Jetty 는 응답 마감일을 둡니다.
Luma 는 정원을 넘는 신청을 대기열로 돌리고 주최자가 승인합니다. 차 좌석이나 방 수가 정해진 여행에 해당합니다.

지금 FIT 는 그룹 여행을 **그룹 멤버 모두가 봅니다.** 그래서 "이 여행에 실제로 가는 사람"이 따로 없습니다.

| 외부 API | 불필요 |
