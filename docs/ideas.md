> 주기적으로 들어올 이유를 만드는 일입니다. 셋 다 **새 기능이 아니라, 이미
> 만든 것들이 서로 안 보이는 문제**를 고칩니다. 그래서 게임처럼 읽히지 않고
> 값도 거의 안 듭니다.

## 1. 소식함 — 내가 없는 동안 뭐가 바뀌었나

### 무엇을

홈에서 여는 **개인 단위** 소식 모음. 여행별이 아니라, 앱을 열자마자 어디서
무슨 일이 있었는지 한자리에서 봅니다.

```
지영님이 둘째 날에 이치란을 넣었어요           2시간 전
민수님이 '어댑터'를 챙긴다고 했어요               어제
후보 3개에 표가 모였어요 — 하나는 전원 찬성
'오사카 3박 4일' 을 12명이 가져갔어요
```

두 갈래를 담습니다.

| 갈래 | 무엇 | 재료 |
|---|---|---|
| **내가 속한 여행** | 장소·날짜 변경, 투표 현황, 챙길 것, 동행자 들고남 | `Place.updatedBy/updatedAt`, `TripCandidate`, `TripItem`, `TripMember` |
| **내가 올린 것** | 추천·댓글·복제 | `PostLike`, `PostComment`, `PostView` |

### 왜 필요한가

데이터가 **이미 다 있습니다.** `Place.updatedBy` · `updatedAt` · `Trip.version`
이 저장되고 `TripDtos` 가 프론트로 내려주기까지 하는데 **어느 화면도 쓰지
않습니다.** 동행자가 일정을 고쳐도 들어가서 전체를 다시 훑어야 압니다.

그래서 협업 기능이 셋(투표장·챙길 것·후보)이나 있는데도 누가 뭘 했는지 안
보여서, 카톡으로 "야 투표해" 를 따로 보내야 합니다.

### 필요한 것

- 사람마다 **마지막으로 본 시각** 한 칸. 이것만으로 "새것" 표시가 됩니다.
- 푸시를 늘리지 않습니다. 들어왔을 때만 보이므로 알림 피로가 0입니다.

### `AuditLog` 는 재사용하지 않습니다

모양은 비슷하지만 색인 기준이 반대입니다.

| | `AuditLog` | 소식함 |
|---|---|---|
| 기준 | **누가 했는가**(actor) | **누구에게 보일 것인가**(수신자) |
| 용도 | 운영자 감사 | 사용자 화면 |
| 보관 | 감사 정책 | 오래되면 버림 |

`place.create` · `post.copy` 같은 기록이 이미 남고 있어 참고는 되지만, 수신자
기준으로 뽑는 질의가 안 나옵니다. 감사 로그에 화면 사정이 섞이면 나중에 둘 다
못 고칩니다.

## 2. D-day — 남은 날을 세어 줍니다

`trips.tsx` 가 이미 "가는 중 · 다가올 · 다녀온" 으로 가릅니다. 날짜를 다 알고
있다는 뜻인데, **남은 날은 안 세어 줍니다.**

사람들은 여행 전에 날짜를 셉니다. 앱이 없어도 하는 행동입니다. 그걸 앱이
대신 세어 주면 그 자체가 들어올 이유가 됩니다.

계산은 이미 되어 있습니다. 홈과 여행 목록에 한 줄 얹는 일이고, 새 데이터도
서버 호출도 없습니다.

---

## 3. 내가 남긴 것이 쓰인 것

소식함과 **같은 화면, 다른 층**입니다. 성격이 달라서 섞으면 한쪽이 다른 쪽을
밀어냅니다.

| | 소식 (1번) | 쌓이는 것 (이것) |
|---|---|---|
| 예 | "지영님이 장소를 넣었어요" | "내 한 줄을 47명이 봤어요" |
| 성격 | 읽으면 지나감 · 새것 표시 | 사라지지 않고 누적 |
| 자리 | 위쪽 목록 | 아래 요약 줄 |

조회 하나하나를 소식으로 올리면 목록이 그것만으로 찹니다. **합쳐서 한 줄**로
둡니다.

### 왜 이것인가

`PlaceTip`(한 줄)은 이 앱에서 **여행이 끝난 뒤에도 계속 값이 생기는 유일한
것**입니다. "2번 출구로 나와야 함" 을 남기면 몇 달 뒤 다른 사람에게 쓰입니다.
그런데 지금은 남기고 끝이라, 자기가 남긴 것이 쓰였는지 알 길이 없습니다.

사람은 자기가 남긴 게 쓰이는 걸 보면 다시 옵니다. 뱃지가 아니라 **실제로
남을 도운 기록**이라, 게임처럼 읽히지 않는 유일한 리텐션 장치입니다.

`PostView` 로 조회를 세는 구조가 이미 있어 같은 패턴을 옮기면 됩니다.

## 아직 정하지 않은 것

- **집계를 언제 하는가.** 볼 때마다 여러 테이블에서 긁어모을지, 쓸 때 소식
  한 줄을 쌓아 둘지. 전자는 테이블이 안 늘고, 후자는 조회가 싸집니다.
  여행 하나에 동행자 2~5명 규모에서는 전자로 시작해도 됩니다.
- **마지막 본 시각을 어디 두는가.** 사람마다 하나인지, 사람 × 여행마다인지.
