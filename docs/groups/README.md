# groups — 모임 · 피드 · 리뷰

> **2026-10-01.** 뼈대를 뒤집는 일입니다. 지금은 여행이 먼저 있고 거기에
> 사람을 부르는데, **무리가 먼저 있고 여행이 그 안에서 생기는** 쪽으로
> 바꿉니다. 그러면서 잘못 자란 자리를 같이 걷어 냅니다.

## 바뀌는 뼈대

```
        지금                           바뀐 뒤

  [여행] ── 초대 ──> 동행자       [그룹] ── 초대 ──> 멤버
     └ 장소마다 도장·기록            └── 여행 여럿
     └ 끝나면 여행기                 [나] └── 혼자 여행

                                  [피드] 사진 + 글 + 태그
                                     └ 그룹에 / 내 것으로
                                  [리뷰] 장소에 별점 + 한 줄
```

## 읽는 순서

```
survey.md    지금 것 중 무엇이 흔들리나 · 바깥은 어떻게 하나
    v
verdict.md   무엇을 넣고 무엇을 빼나          ← 먼저 읽어도 됩니다
    v
spec.md      기능명세서 — 데이터 · 규칙 · API
screens.md   화면정의서 — 화면 열하나
    v
plan.md      다섯 덩어리로 끊은 순서
```

바쁘면 **`verdict.md` 와 `plan.md` 둘만** 읽으면 됩니다.

> `survey.md` 는 **처음 설계(여행 멤버를 남겨 두는 안)** 를 기준으로 쓰였고,
> 그 뒤 「여행 멤버를 없애고 그룹으로 합친다 · 도장을 뺀다」로 바뀌었습니다.
> 조사한 사실은 그대로 쓸모 있지만, **결론은 `verdict.md` 가 최신입니다.**

## 한 줄 요약

| | |
|---|---|
| **넣는다** | 그룹 · 피드(사진+글+자유태그, 댓글만) · 내 여행 탭 둘 · 장소 리뷰(별점) · 마이페이지 · 그룹 소식 |
| **뺀다** | **도장** · 장소마다 기록 · **여행 멤버/초대** · 여행 피드 화면 · 보기만 역할 |
| **안 한다** | 채팅 · 공개 그룹 · 친구 · 그룹 가계부 · 좋아요 |
| **새 표** | `groups` `group_members` `group_invites` `posts` `post_photos` |
| **없애는 표** | `trip_members` `trip_invites` |
| **기존 변경** | `trips.group_id` · `post_comments.kind` · `place_tips.stars` · `places` 네 칸 빼기 |
| **단계** | 0 걷어내기 → 1 그룹 → 2 피드 → 3 여행기에 글 싣기 → 4 리뷰·마이페이지 |

## 가장 조심할 자리 셋

**`TripAccessPolicy`** — 13개 파일 48군데가 지나갑니다. 잘못 고치면 남의
여행이 보이거나 내 여행이 안 보입니다. 1단계에서 시험을 먼저 씁니다.

**되돌릴 수 없는 마이그레이션** — 여행 멤버를 그룹으로 옮기고 표를 지웁니다.
지금 쓰는 사람이 혼자라 값이 작고, **그래서 지금 하는 것**이 맞습니다.

**둘러보기에서 사진이 잠깐 사라집니다** — 공개 여행기에 실리는 사진이 전부
장소 기록에서 나옵니다. 0단계에서 걷어 내고 3단계에서 피드 글로 돌아옵니다.
그 사이에 올리는 글에는 사진이 없습니다. **0→3 을 빨리 가야 합니다.**
