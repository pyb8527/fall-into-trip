# groups — 모임

> **2026-10-01.** 여행을 여러 번 같이 가는 무리에게 그 무리를 담을 자리를
> 주는 일. 앞의 세 폴더와 달리 **기능 하나를 깊게** 봅니다.

## 왜 이 폴더가 생겼나

지금 앱에서 여행 하나는 **닫힌 방**이고, 바깥과 만나는 길은 「끝나고 여행기로
내놓기」 하나뿐입니다. 그래서 여행이 끝나면 그 사람들과의 끈도 같이
끝납니다 — 작년에 같이 간 사람과 올해 또 가려면 초대 링크를 다시 보내야 하고,
둘이 같은 무리라는 것을 앱은 모릅니다.

## 읽는 순서

```
survey.md    지금 것 중 무엇이 흔들리나 · 바깥은 어떻게 하나
    v
verdict.md   무엇을 하고 무엇을 안 하나          ← 먼저 읽어도 됩니다
    v
spec.md      기능명세서 — 데이터 · 규칙 · API
screens.md   화면정의서 — 화면 열 · 기존 화면에 생기는 변화
    v
plan.md      네 덩어리로 끊은 순서
```

바쁘면 **`verdict.md` 와 `plan.md` 둘만** 읽으면 됩니다. 나머지는 그 둘의
근거입니다.

## 한 줄 요약

| | |
|---|---|
| **한다** | 그룹 · 그룹 피드 · 마이페이지 · 그룹 소식 · (나중에) 사진첩 |
| **안 한다** | 채팅 · 공개 그룹 · 친구 · 그룹 가계부 |
| **새 표** | `groups` `group_members` `group_invites` `group_posts` `group_post_photos` (+`group_photos`) |
| **기존 변경** | `trips.group_id` · `post_comments.kind` · `TripAccessPolicy` |
| **단계** | 1 그룹 → 2 피드 → 3 마이페이지 → 4 사진첩(별개) |

## 가장 조심할 자리 둘

**`TripAccessPolicy`** — 여행의 모든 길이 이것 하나를 지나갑니다. 잘못 늘리면
남의 여행이 보이거나 내 여행이 안 보입니다. 1단계에서 시험을 먼저 씁니다.

**사진 용량** — 그룹 사진첩은 서버 옆 폴더로 못 받습니다. 그래서 4단계는
앞의 셋과 묶지 않았습니다.

- [ ] 1단계를 지금 시작할 것인가
