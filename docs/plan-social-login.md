# 구글로 로그인한다

> 조사에서 나온 것이 아닙니다. **지금 가입에 비밀번호를 만들게 하는 것이
> 가장 큰 문턱**이라 만드는 사람이 정한 일입니다.
>
> 아직 코드는 한 줄도 바뀌지 않았습니다.

## 1. 하려는 것

지금 가입하려면 이메일과 **새 비밀번호**를 만들어야 합니다. 여행 한 번
같이 가자고 부른 사람에게 그것부터 시키고 있습니다.

구글 계정으로 한 번 누르면 들어오게 합니다.

## 2. 애플은 이번에 안 합니다

같이 하려다 미뤘습니다. 웹에서 애플 로그인을 하려면 **유료 개발자
계정($99/년)** 과 Services ID·키·도메인 검증이 필요합니다. 앱을 스토어에
올릴 때 어차피 그 계정이 있어야 하므로 **그때 묶습니다.**

그때가 오면 이 문서의 길을 그대로 씁니다 — JWKS 주소와 `iss`·`aud` 만
다릅니다. 그래서 §5 를 **갈래가 늘어날 것을 알고** 짭니다.

> 스토어에 올릴 때는 고르는 것이 아니라 **의무**입니다. 다른 소셜 로그인을
> 두면 애플이 Sign in with Apple 을 함께 두도록 요구합니다.

## 3. 가장 조심할 것 — 계정 잇기

**이 앱은 가입할 때 이메일을 한 번도 확인하지 않습니다.**
(`AuthService.register` — `Email.of` 는 모양만 봅니다.)

그래서 "이메일이 같으면 잇는다" 를 그냥 두면 이런 길이 열립니다.

```
1. 남이 내 이메일로 비밀번호 계정을 먼저 만들어 둔다  (확인 절차가 없으니 됩니다)
2. 내가 구글로 로그인한다
3. 이메일이 같으니 그 계정으로 들어간다 → 남의 계정 안입니다
```

**자동으로 잇는 것은 곧 그 계정으로 로그인시켜 주는 것**이라 이것이 그대로
계정 탈취가 됩니다.

### 그래서 이렇게 가릅니다

| 그 이메일의 계정이 | 어떻게 |
|---|---|
| 없음 | **새로 만듭니다.** 비밀번호 없이 |
| 있고 **비밀번호가 없음** | **잇습니다.** 소셜로만 만들어진 계정이라 선점할 방법이 없습니다 |
| 있고 **비밀번호가 있음** | **안 잇습니다.** "이미 가입된 주소입니다. 로그인한 뒤 설정에서 구글을 이으세요" |

셋째가 한 번 번거롭습니다. 그 대신 **남이 먼저 선점해 둬도 안 들어갑니다.**

### 확인 안 된 이메일은 안 받습니다

구글이 `email_verified: false` 로 주면 거절합니다. 회사 계정 중에 그런 것이
있습니다.

## 4. 갈 곳

```
[웹]  구글 단추를 누른다
        |
        v
  구글이 ID 토큰(JWT)을 내준다      ← 브라우저 안에서
        |
        v
  POST /api/auth/google { credential }
        |
        v
  토큰을 검증한다 — 서명 · iss · aud · exp · email_verified
        |
        v
  (provider, subject) 로 이미 아는 사람인가?
        |                        |
       예                       아니오
        |                        |
        v                        v
     그 사람             이메일로 §3 의 세 갈래
        |                        |
        +------------+-----------+
                     v
              withNewSession      ← 지금 로그인과 같은 자리
```

**`withNewSession` 으로 모입니다.** 액세스 토큰과 리프레시 쿠키를 내주는
자리가 하나라, 소셜이 붙어도 세션 규칙은 안 갈라집니다.

## 5. 토큰을 손으로 검증하지 않습니다

`spring-boot-starter-oauth2-resource-server` 를 더합니다. 거기 든
`NimbusJwtDecoder` 가 이것을 다 합니다.

| 해 주는 것 | 손으로 짜면 |
|---|---|
| JWKS 내려받기와 **캐시** | 매번 받으면 느리고, 안 받으면 키 교체 때 죽습니다 |
| **키 교체** 따라가기 | 구글이 키를 바꾸면 어느 날 갑자기 전부 로그인 실패 |
| 서명 · `exp` · 시계 오차 | 보안 구멍이 정확히 여기서 납니다 |

우리가 얹는 것은 **`iss` 와 `aud`** 둘뿐입니다.

의존을 하나 더 다는 것이 이 저장소 취향과 어긋나지만, **손으로 짤 것이
암호 검증**이라 여기서는 라이브러리가 맞습니다. 스프링이 버전을 잡아 주므로
버전 관리도 안 늘어납니다.

### 갈래가 늘어날 자리

`SocialToken` 하나를 두고 제공자마다 `(jwkSetUri, issuer, audience)` 만
다르게 둡니다. 애플이 올 때 그 줄 하나가 늘고 나머지는 그대로입니다.

## 6. 닿는 파일

| 파일 | 무엇을 |
|---|---|
| `backend/build.gradle` | `oauth2-resource-server` 한 줄 |
| `V23__social_login.sql` | `users.password_hash` 를 널 허용으로, `user_identities` 표 |
| `account/domain/UserIdentity.java` | 새로. `(provider, subject)` 가 열쇠 |
| `account/domain/UserIdentityRepository.java` | 새로 |
| `account/domain/User.java` | `passwordHash` 가 없을 수 있음 |
| `account/application/SocialAuthService.java` | 새로. §3 의 세 갈래 |
| `account/infrastructure/security/SocialTokens.java` | 새로. 토큰 검증 |
| `account/api/AuthController.java` | `POST /api/auth/google`, 잇기·끊기 |
| `SecurityConfig` | `/api/auth/google` 를 열어 둡니다 |
| `frontend/src/lib/social.web.ts` · `social.ts` | 웹에만 구글 단추 |
| `frontend/src/app/(auth)/login.tsx` · `register.tsx` | 단추 |
| `frontend/src/app/(app)/settings.tsx` | 잇기·끊기 |

### 6.1 비밀번호가 없어지는 자리들

`password_hash` 가 널이 되면 이 셋이 걸립니다. **함께 고칩니다.**

| 어디 | 지금 | 고쳐서 |
|---|---|---|
| `login` | `encoder.matches(pw, hash)` | 해시가 없으면 **바로 실패**. "구글로 로그인해 주세요" 가 아니라 지금 문구 그대로 — 어느 주소가 소셜인지 알려 주는 통로가 됩니다 |
| `changePassword` | 현재 비밀번호를 봅니다 | 해시가 없으면 현재 것을 안 묻고 **새로 만듭니다** |
| 설정 화면 | "비밀번호 바꾸기" | 없으면 "비밀번호 만들기" |

### 6.2 끊기

구글을 끊을 수 있어야 합니다. 다만 **끊고 나서 들어올 길이 없으면 안
됩니다** — 비밀번호가 없고 이은 제공자가 그것 하나뿐이면 거절합니다.

## 7. API

| | |
|---|---|
| `POST /api/auth/google` | 몸통 `{ credential }`. 로그인 응답은 **지금과 같은 모양** |
| `POST /api/auth/link/google` | 로그인한 사람이 자기 계정에 이음 |
| `DELETE /api/auth/link/google` | 끊음. 6.2 의 조건 |

실패:

| | |
|---|---|
| 400 | 토큰이 틀렸거나 `email_verified` 가 아님 |
| 409 | **비밀번호 계정이 이미 그 이메일을 씁니다** — §3 의 셋째 |
| 400 | 끊으면 들어올 길이 없음 |

## 8. 테스트

`backend/src/test/http/social.test.mjs` 를 새로 만듭니다.

**구글 토큰을 만들 수 없으니 통과하는 길은 여기서 못 봅니다.** 그 앞의
울타리를 봅니다 — `place`·`recommend` 가 구글 키 없이 도는 방식과 같습니다.

| 무엇을 | |
|---|---|
| 토큰 없이 부르면 400 | |
| 엉터리 토큰이면 400 | 서명이 안 맞습니다 |
| **로그인 없이 잇기를 부르면 401** | |

기존 `auth.test.mjs` 36개가 그대로 통과해야 합니다. 그것이 이 작업에서
가장 중요한 시험입니다.

## 9. 아직 모르는 것

- **구글 클라이언트 ID 를 형님이 만들어 주셔야** 끝까지 갑니다. 그 전까지는
  울타리까지만 잽니다. `.env` 에 `GOOGLE_CLIENT_ID` 로 받습니다.
- **웹에서 단추를 어떻게 그릴지.** 구글이 주는 기본 단추는 이 앱의 흑백·각진
  결과 안 맞습니다. 직접 그리면 구글 브랜드 규칙을 지켜야 합니다.
- **앱(iOS·Android)은 이번에 안 합니다.** 네이티브 로그인은 EAS 재빌드가
  필요하고, 그건 앱 작업 때 묶기로 한 것입니다.

## 10. 만들었습니다 (2026-09-14)

**구글만입니다.** 애플은 §2 대로 앱 작업 때 묶습니다.

| 어디 | 무엇 |
|---|---|
| `build.gradle` | `oauth2-resource-server` |
| `V23__social_login.sql` | `password_hash` 널 허용, `user_identities` |
| `UserIdentity` · `UserIdentityRepository` | 열쇠가 `(provider, subject)` |
| `User.hasPassword()` | 해시를 견주는 자리마다 먼저 봅니다 |
| `SocialTokens` | 토큰 검증. 애플은 `decoderFor` 에 갈래 한 줄 |
| `SocialAuthService` | §3 의 세 갈래, 잇기, 끊기 |
| `AuthController` | `/google`, `/link/google`, `/link/{provider}` |
| `auth-panel.tsx` · `settings.tsx` | 단추와 잇기 칸 |

### 10.1 클라이언트 ID 를 빌드에 안 박았습니다

계획서에 없던 판단입니다. `GET /api/auth/state` 가 내려보냅니다.

빌드에 박으면 값을 바꿀 때마다 웹을 다시 구워야 하고, **`.env` 와 번들이
어긋난 채로 도는 날**이 옵니다. 비밀이 아니라 브라우저에 나가도 되는
값입니다 — 진짜 확인은 서명입니다.

덕분에 형님이 `.env` 에 `GOOGLE_CLIENT_ID` 만 넣고 다시 띄우면 단추가
생깁니다. 웹을 다시 안 구워도 됩니다.

### 10.2 구글이 그리는 단추를 씁니다

직접 그리면 이 앱의 흑백·각진 결에 맞출 수 있지만 구글 로고와 문구에는
규칙이 있습니다. 대신 구글이 주는 것 중 **검은 채움 · 네모**를 골랐습니다.

스크립트는 그 단추가 그려지는 자리에서만 받습니다. 미리 받아 두면 구글
로그인을 안 쓰는 사람도 열 때마다 구글에 다녀오게 됩니다.

### 10.3 잰 것

**가장 무서운 자리를 손으로 재 봤습니다.** `password_hash` 가 널인 계정을
직접 만들어 놓고 네 가지로 들어가 봤습니다.

| 넣은 비밀번호 | |
|---|---|
| 빈 문자열 | 400 막힘 |
| 아무 비밀번호 | 401 막힘 |
| `"null"` | 401 막힘 |
| 해시처럼 생긴 글자 | 401 막힘 |

`.mjs` 묶음에는 못 넣었습니다 — 그런 계정을 만들려면 구글 토큰이 필요해서
API 만으로는 안 됩니다. **나중에 이 자리를 건드리면 손으로 다시 재야
합니다.**

| | |
|---|---|
| `social.test.mjs` | **15 통과 / 0 실패** (새로) |
| `auth.test.mjs` | **36 통과 / 0 실패** — 안 깨지는 것이 제일 중요했습니다 |
| admin 56 · guest 34 · invite 46 · trip 60 · news 54 | 전부 0 실패 |
| `./gradlew test` | 27 통과 |
| typecheck · web export | 통과 |

위조 토큰(모양은 JWT, 서명은 없음)으로 들어가 보는 시험을 넣었습니다.
서명을 안 보면 그것이 통과하고, 그러면 **아무나 남의 이메일을 적어 넣어
그 계정으로 들어옵니다.**

### 10.4 아직 안 잰 것 — 형님이 열어야 합니다

**Google Cloud 콘솔에서 OAuth 2.0 클라이언트 ID(웹)를 만들어** `.env` 의
`GOOGLE_CLIENT_ID` 에 넣어 주세요. 승인된 자바스크립트 원본에 서비스 주소를
넣어야 합니다.

그 전까지는 단추가 **안 뜹니다.** 눌러도 안 되는 단추를 두지 않습니다.

넣고 나서 볼 것:

| | |
|---|---|
| 처음 보는 구글 계정 | 새 계정이 만들어지고 바로 들어감 |
| **이미 비밀번호로 가입한 주소** | 409 와 "설정에서 이어 주세요" |
| 설정에서 이은 뒤 | 구글 단추 하나로 들어감 |
| 구글로만 들어온 사람의 설정 | "비밀번호 만들기" 가 떠야 합니다(현재 것을 안 물음) |
| 그 사람이 구글을 끊으려 하면 | 거절 — 들어올 길이 없어집니다 |
