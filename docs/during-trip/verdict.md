### 0.1 이번 조사에는 1차가 없습니다

지난 조사(`docs/2026-09/verdict.md`)는 1차 — **재빌드도 서버 변경도 없는 것** —
에 넷을 담았습니다. 이번에는 **하나도 없습니다.**

받기로 한 다섯을 세어 보면 이렇습니다.

| 받는 것 | 무엇이 필요한가 |
|---|---|
| 5 날씨 | 서버 (새 바깥문) |
| 6 환율 어림 | 서버 (새 바깥문) |
| 4 실시간 출발 | 서버 (구글 호출 늘어남) |
| 1 현지 글자 이름 | 서버 + 스키마 |
| 12.2 빨리 넣기 | EAS 재빌드 |

**여행 중 기능에는 싼 것이 없습니다.** 이유가 분명합니다 — 계획은 이미 우리
DB 에 있는 것을 다시 보여 주는 일이 많고, 여행 중은 **지금 바깥에서 벌어지는
일**을 알아야 합니다. 날씨·열차·환율·혼잡도가 다 그렇습니다.

그래서 이 문서의 순서는 "싼 것부터" 가 아니라 **"바깥문을 몇 개 새로 여는가"**
로 매겼습니다.

### 0.2 새 바깥문은 아무도 세지 않습니다

지난 조사가 `GoogleQuotaFilter` 의 눈먼 자리를 하나 찾았습니다 — 필드마스크로
요금 등급이 올라가는 것을 못 본다는 것(`docs/2026-09/verdict.md` 0.2).

이번에는 **더 큰 눈먼 자리**가 보입니다. 그 문턱은 이름 그대로 **구글만**
셉니다.

```java
static int callsOf(String method, String path) {
    if (path.startsWith("/api/places/search")) { return 1; }
    ...
}
```

날씨 API 를 붙이면 그 호출은 `callsOf` 에 0 입니다. 항공 API 도, 환율도,
혼잡도도 0 입니다. **문턱이 없는 바깥문이 열리는 것**이고, 그쪽은 월정액이라
과금 모양도 구글과 다릅니다(횟수가 아니라 한도).

**그래서 5·6번의 조건에 "문턱을 함께 만든다" 를 넣었습니다.** 붙이고 나서
세는 것을 잊으면, 지금 구글에 대해 서 있는 규율이 새 문에는 안 서 있는
상태가 됩니다.

## 1. 메뉴와 간판을 그 자리에서 읽기 — **재설계 권장**

### 걸리는 것 — 원래 모양으로는 안 됩니다

| | |
|---|---|
| 카메라 의존 | `frontend/package.json` 에 카메라·마이크·오디오 의존이 **하나도 없습니다.** 새로 넣어야 하고 EAS 재빌드가 붙습니다 |
| 웹에서 안 됩니다 | Chrome 의 Translator API 는 **데스크톱 전용**입니다. 문서가 그대로 적었습니다. 이 앱의 실제 서비스는 nginx 가 내보내는 웹 빌드이고, 여행 중에는 폰으로 엽니다 |
| 우리가 나을 수 없습니다 | Google Translate 는 오프라인 70개 언어에 카메라 번역까지 합니다. 우리 기기 안 모델은 Qwen 2.5 1.5B 하나입니다 |

**이것을 받으면 값을 치르는 것**은 웹입니다. 온디바이스 모델이 웹과 앱을
가르는 첫 자리였고(`docs/done/recommend.md` §8.1), 위젯이 두 번째였습니다
(`docs/2026-09/plan-widget.md` §3.4). 카메라 번역은 **웹에서 아예 성립하지
않는** 세 번째가 됩니다. 그런데 얻는 것은 사람들이 이미 폰에 깔아 둔 앱이
더 잘 하는 일입니다.

### 문제의식은 맞습니다 — 붙는 자리가 다릅니다

조사가 말한 문제는 "현지 글자를 못 읽는다" 입니다. 그런데 **FIT 이 실제로
겪게 하는 문제는 그 반대입니다.**

`PlaceSearchService.java:111`:

```java
ask.put("languageCode", "ko");
```

**못박혀 있습니다.** 그래서 오사카의 가게가 "난바 파크스" 로 들어오고,
`Place.name` 에 그 한국어만 저장됩니다(`trip/domain/Place.java`). 현지 글자는
**어디에도 없습니다.**

길 위에서 일어나는 일이 이것입니다.

- 간판에는 「なんばパークス」 라고 적혀 있는데 폰에는 "난바 파크스" 만 있어
  같은 곳인지 확신이 안 섭니다.
- 택시 기사에게 폰을 보여 줘도 못 읽습니다.
- 가게 사람에게 물을 때 댈 이름이 없습니다.

**카메라로 읽는 것보다 이쪽이 먼저입니다.** 번역할 글자가 눈앞에 있을 때는
번역 앱을 켜면 되지만, **폰에 든 이름이 현지에서 안 통하는 것**은 우리가
만든 문제이고 우리만 고칠 수 있습니다.

### 고쳐 받는 모양

장소를 **담을 때 한 번** 현지 글자 이름을 함께 받아 저장합니다. 화면에서는
한국어 이름 아래 작게 둡니다.

### 값

| | |
|---|---|
| 새 외부 의존 | 없음 |
| 구글 호출 | **+1** — 담을 때 한 번. `callsOf` 의 해당 자리에 더합니다 |
| 요금 등급 | **안 오릅니다** — `displayName` 은 Pro 이고 이미 받고 있습니다 |
| 서버 저장 | 글자 한 칸 |
| EAS 재빌드 | **필요 없음** |
| 스키마 변경 | **필요** — `Place` 에 칸 하나 |
| 백엔드 변경 | 기존 서비스 수정 (`PlaceSearchService`·`PlaceService`) |

### 지켜야 할 것

- **볼 때마다 부르지 않습니다.** 담을 때 한 번입니다. 화면을 열 때마다
  부르면 호출이 장소 수만큼 늘고, 그 값을 `callsOf` 가 세기 어렵습니다.
- **못 받아 오면 그 줄을 안 냅니다.** 한국 장소에는 현지 글자가 한국어라
  같은 이름이 두 번 나옵니다. 같으면 안 보여 줍니다. "아는 것만 말합니다."
- `Found` 레코드의 기존 칸을 바꾸지 않습니다.

조사가 밝힌 것 — 구글 지도 오프라인에서도 **대중교통 길찾기와 실시간 교통은

## 5. 그날 그 시각의 날씨 — **조건부 찬성 · 1순위**

### 없습니다

`backend/src/main/java` 와 `frontend/src` 전체에 `weather`·`forecast`·`날씨`·
`기온` 이 **하나도 없습니다.**

### 왜 이것이 1순위인가

**이미 만든 것 하나가 날씨를 전제로 서 있는데 정작 날씨를 모릅니다.**

`RecommendService` 의 주석과 `docs/done/recommend.md` 가 드는 예가 처음부터
이것이었습니다.

> "오사카에서 **비 올 때** 갈 만한 실내"

사람이 그 문장을 적을 수 있게 만들어 두었습니다. 그런데 **비가 오는지 우리는
모릅니다.** 사람이 창밖을 보고 스스로 판단해서 그 문장을 적어야 합니다.
날씨를 알면 그 자리에서 먼저 물을 수 있습니다.

그리고 붙는 자리가 이미 있습니다. `Day` 마다 `iso`(날짜)가 있고
(`trip/domain/Day.java`), 그 날의 장소들에 좌표가 있습니다. 트리플이
일정판에서 바로 보여 주는 것과 같은 자리입니다.

### 값 — 여기가 갈림입니다

| | Open-Meteo | OpenWeatherMap |
|---|---|---|
| 키 | 비상업은 필요 없음 | 무료 등급도 필요 |
| 무료 | **비상업 전용.** 하루 10,000 | 월 100만, 분당 60 |
| 상업 | **월 $29 부터** (무료 등급이 없어집니다) | 무료 등급 있음 |

**이 앱이 상업인지가 곧 월 $29 의 갈림입니다.** 그 답을 제가 모릅니다 —
아래 "아직 모르는 것" 에 두었습니다.

### 조건 넷

**(ㄱ) 상업 여부를 먼저 정하고 출처를 고릅니다.** 비상업이면 Open-Meteo 가
키도 없이 됩니다. 상업이면 OpenWeatherMap 의 무료 등급이 값이 안 듭니다.
**모호하면 상업으로 봅니다** — 약관을 어기고 쓰는 것보다 낫습니다.

**(ㄴ) 문턱을 함께 만듭니다.** `GoogleQuotaFilter` 는 구글만 셉니다(0.2).
날씨는 아무도 안 세므로, 붙일 때 세는 자리를 같이 만듭니다. 안 하면 규율이
새 문에는 안 서 있는 상태가 됩니다.

**(ㄷ) 하루를 통째로 묻습니다.** 장소마다 부르지 않습니다.
`DayExtrasController:58` 의 `places-info` 가 이미 같은 판단을 했습니다 —

- **10 지갑 패스** — 우리가 파는 티켓이 없어서 넣을 것이 없습니다. 게다가
  패스를 서명해 내주면 파일이 생깁니다.
- **11 항공편 상태** — 월 $49.99 부터인데 정작 게이트는 엔터프라이즈 등급에
  잠겨 있습니다. Flighty 가 훨씬 잘 합니다.
- **12.1 영수증 사진** — 서버에 파일을 안 쌓습니다.
- **1 의 원래 모양(카메라 번역)** — 웹에서 성립하지 않고, Google Translate
  가 오프라인 70개 언어로 이미 합니다. 문제의식만 받아 §1 로 고쳤습니다.

## 조사에 없었지만 눈에 띈 자리

`survey.md` 의 "아무도 안 하는 것" 에 적은 둘입니다. 후보가 아니라 **다음
조사거리**로 남깁니다 — 이번 판정에 넣지 않았습니다.

**여행 중에 일정이 흐트러지는 것.** 비가 오거나 줄이 길어서 하나를 건너뛰면
그 뒤가 전부 밀립니다. 조사한 열셋 중 이것을 다루는 것이 없었습니다. 그런데
**FIT 에는 붙을 자리가 이미 서 있습니다** — `trip/domain/RouteTidy.java` 의
제안 → 비교 → 수락 → 되돌리기, 그리고 "사람이 수락해야 바뀝니다" 규칙.
지금 그 장치가 동선 정리에만 쓰이고 있습니다.

**길 위에서 다시 합의하는 것.** `CandidateService`(전원 동의)가 계획 단계에만
쓰입니다. "지금 여기서 하나를 빼야 하는데 다들 괜찮은가" 를 묻는 자리가
없습니다.

둘 다 **바깥문을 하나도 안 엽니다.** 이번 조사에서 받은 다섯이 전부 새 문이나
재빌드를 요구하는 것과 다릅니다. 다음 조사를 이쪽으로 하면 1차가 다시 생길
가능성이 큽니다.
